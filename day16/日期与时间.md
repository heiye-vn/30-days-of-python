# Python 日期与时间核心教程：从标准库到项目实战

时间与日期是软件开发中不可或缺的基石。无论是记录日志、计算 Token 过期时间、处理跨国时区，还是评估代码执行效率，Python 都提供了丰富的原生支持。

本文将为您全面解析 Python 标准库中的三个核心时间模块：`datetime`、`time` 和 `timeit`，以及 Python 3.9+ 新增的 `zoneinfo` 时区模块与 `calendar` 日历模块。同时引入第三方时间库（`arrow`、`pendulum`）进行对比，并结合 4 大实际项目场景提供最佳实践。

---

## 1. 核心概念与思维模型

在开始编写代码前，必须建立正确的物理与逻辑时间模型：

- **时间戳 (Timestamp)**：从格林威治时间 1970年01月01日00时00分00秒（北京时间 1970年01月01日08时00分00秒）起至现在的总秒数。时间戳是绝对的，不受时区影响。
- **结构化时间 (struct_time)**：将时间表示为一个包含 9 个元素的元组（如年、月、日、时、分、秒、星期等），方便访问各个时间分量。
- **格林威治标准时间 (UTC)**：全球通用的基准时间，比北京时间（东八区 UTC+8）慢 8 小时。
- **时区分类 (Naive vs Aware)**：
  - **Naive (无时区感知)**：没有包含时区信息。它无法判断自己相对于 UTC 的位置。例如 `datetime.now()` 默认返回的对象。
  - **Aware (有时区感知)**：包含了明确的时区信息（如 `tzinfo` 属性），可以准确地在多国时区之间转换。

## 2. `datetime` 模块：面向对象的日期与时间操作

`datetime` 是 Python 处理日常业务逻辑中最常用的模块，它主要由以下几个核心类组成：

### 2.1 `datetime.date` 类
仅表示日期，不包含具体的时间和时区。
- **常用操作**：
```python
from datetime import date

# 获取今天的日期
today = date.today()
print(f"今日日期: {today}")  # 输出: 2026-06-30 (示例)
print(f"年: {today.year}, 月: {today.month}, 日: {today.day}")

# 创建指定日期
specific_date = date(2026, 10, 1)
print(f"国庆节: {specific_date}")
```

### 2.2 `datetime.time` 类
仅表示时间，不包含具体的日期。
- **常用操作**：
```python
from datetime import time

# 创建一个时间对象 (时, 分, 秒, 微秒)
t = time(14, 30, 45, 500)
print(f"指定时间: {t}")  # 输出: 14:30:45.000500
print(f"时: {t.hour}, 分: {t.minute}, 秒: {t.second}")
```

### 2.3 `datetime.datetime` 类
同时包含日期与时间，是实际项目中最常打交道的类。
- **常用操作**：
```python
from datetime import datetime, timezone

# 1. 获取当前本地时间 (Naive)
now_naive = datetime.now()
print(f"本地 Naive 时间: {now_naive}")

# 2. 获取当前 UTC 时间 (Aware, 推荐方式)
now_utc = datetime.now(timezone.utc)
print(f"UTC Aware 时间: {now_utc}")

# 3. 拼接日期与时间
d = date(2026, 6, 30)
t = time(9, 30, 0)
combined = datetime.combine(d, t)
print(f"拼接后的 datetime: {combined}")
```

### 2.4 `datetime.timedelta` 类
表示两个日期或时间之间的时间差，主要用于日期的加减运算。
- **核心参数**：支持 `weeks`, `days`, `hours`, `minutes`, `seconds`, `microseconds`, `milliseconds`。
- **常用操作**：
```python
from datetime import datetime, timedelta

now = datetime.now()

# 加上 7 天
next_week = now + timedelta(days=7)
# 减去 3 小时
three_hours_ago = now - timedelta(hours=3)

print(f"一周后: {next_week}")
print(f"三小时前: {three_hours_ago}")

# 计算两个日期之间的差值
delta = next_week - now
print(f"相差天数: {delta.days} 天，相差秒数: {delta.total_seconds()} 秒")
```

### 2.5 `datetime.timezone` 与 `tzinfo` 类
`tzinfo` 是时区的抽象基类，而在日常开发中，我们主要使用其具体子类 `datetime.timezone` 来显式声明时区。
- **常用操作**：
```python
from datetime import datetime, timezone, timedelta

# 创建北京时间 (东八区, UTC+8)
tz_bj = timezone(timedelta(hours=8))

# 获取带北京时区的当前时间
now_bj = datetime.now(tz_bj)
print(f"当前北京时间: {now_bj}")  # 会带上 +08:00 后缀
```

### 2.6 `strftime` / `strptime` 格式化符号速查表

格式化符号是 `strftime`（格式化输出）和 `strptime`（解析输入）共用的，按大小写分组记忆效果最佳：

| 符号 | 含义 | 示例 | 备注 |
| :--- | :--- | :--- | :--- |
| **日期相关** | | | |
| `%Y` | 四位数年份 | `2026` | 大写 Y = 完整年份 |
| `%y` | 两位数年份 | `26` | 小写 y = 缩写年份 |
| `%m` | 两位数月份 | `01` ~ `12` | ⚠️ 小写 m = **月份** |
| `%d` | 两位数日期 | `01` ~ `31` | |
| `%B` | 月份全称 | `October` | 大写 B = 全称 |
| `%b` | 月份简写 | `Oct` | 小写 b = 缩写 |
| `%h` | 月份简写（同 `%b`） | `Oct` | POSIX 扩展，`%b` 的别名 |
| **星期相关** | | | |
| `%A` | 星期全称 | `Friday` | 大写 A = 全称 |
| `%a` | 星期简写 | `Fri` | 小写 a = 缩写 |
| `%w` | 星期数字 | `0`(周日) ~ `6`(周六) | |
| **时间相关** | | | |
| `%H` | 24 小时制 | `00` ~ `23` | 大写 H |
| `%I` | 12 小时制 | `01` ~ `12` | 大写 I |
| `%M` | 两位数分钟 | `00` ~ `59` | ⚠️ 大写 M = **分钟** |
| `%S` | 秒 | `00` ~ `59` | |
| `%f` | 微秒 | `000000` ~ `999999` | 6 位补零 |
| `%p` | 上午/下午 | `AM` / `PM` | 配合 `%I` 使用 |
| **时区相关** | | | |
| `%z` | UTC 偏移量 | `+0800`, `-0500` | |
| `%Z` | 时区名称 | `CST`, `UTC` | |
| **复合/其他** | | | |
| `%j` | 一年中第几天 | `001` ~ `366` | |
| `%U` | 一年中第几周 | `00` ~ `53` | 以**周日**为每周第一天 |
| `%W` | 一年中第几周 | `00` ~ `53` | 以**周一**为每周第一天 |
| `%c` | 本地日期时间表示 | `Mon Jun 30 09:30:00 2026` | 等价于 `%a %b %d %H:%M:%S %Y` |
| `%x` | 本地日期表示 | `06/30/26` | |
| `%X` | 本地时间表示 | `09:30:00` | |
| `%%` | 字面量 `%` | `%` | 转义用 |

> **记忆口诀**：大写管"大"（完整年份 `%Y`、完整月名 `%B`、完整星期 `%A`、24 小时 `%H`、分钟 `%M`），小写管"小"（缩写年份 `%y`、缩写月名 `%b`、缩写星期 `%a`、月份 `%m`）。**唯一要死记的反直觉项**：`%m` (小写) = 月份，`%M` (大写) = 分钟。

## 3. `time` 模块：底层系统时间与性能基础

`time` 模块偏向底层，直接调用 C 语言级别的系统时间 API。它的效率极高，主要处理时间戳、系统延迟及 CPU 性能度量。

### 3.1 核心概念转换
`time` 模块主要包含三种时间格式的互相转换：**时间戳 (Float)**、**结构化时间 (struct_time)**、**格式化字符串 (String)**。

```mermaid
graph TD
    A[时间戳 Float<br>time.time()] -->|time.localtime()| B(结构化时间 struct_time)
    A -->|time.gmtime()| C(UTC 结构化时间)
    B -->|time.strftime()| D(格式化字符串)
    D -->|time.strptime()| B
    B -->|time.mktime()| A
```

### 3.2 常用 API 与示例
```python
import time

# 1. 获取当前时间戳
timestamp = time.time()
print(f"当前时间戳: {timestamp}")  # 输出如: 1782782362.12345

# 2. 时间戳转本地结构化时间
local_struct = time.localtime(timestamp)
print(f"本地年份: {local_struct.tm_year}, 星期几: {local_struct.tm_wday}")

# 3. 结构化时间转格式化字符串
time_str = time.strftime("%Y-%m-%d %H:%M:%S", local_struct)
print(f"格式化输出: {time_str}")

# 4. 字符串解析为结构化时间
parsed_struct = time.strptime("2026-06-30 18:30:00", "%Y-%m-%d %H:%M:%S")
print(f"解析后的年份: {parsed_struct.tm_year}")

# 5. 使当前线程休眠 1.5 秒
time.sleep(1.5)
```

### 3.3 `perf_counter()` vs `monotonic()` vs `time()`

`time` 模块提供了三种获取时间的函数，它们的适用场景各不相同：

| 函数 | 精度 | 是否单调递增 | 包含 sleep 时间 | 典型用途 |
| :--- | :--- | :--- | :--- | :--- |
| `time.time()` | 中等 | ❌ 可能倒退 | 是 | 获取时间戳、与外部系统交互 |
| `time.perf_counter()` | **最高** | ✅ | 是 | 性能基准测试、代码耗时统计 |
| `time.monotonic()` | 高 | ✅ | 是 | 超时判断、调度器、重试间隔 |

> **选择建议**：测代码性能用 `perf_counter()`，做超时/调度用 `monotonic()`，获取真实时间戳用 `time()`。

## 4. `timeit` 模块：小段代码性能基准测试

在性能分析中，我们不应当使用 `time.time()` 来测试代码执行效率。因为垃圾回收、系统中断等因素会导致测量结果出现极大的误差。`timeit` 模块是官方提供的基准测试工具，默认执行 1,000,000 次代码并返回总耗时（秒），有效消除单次运行的随机误差。

### 4.1 常用 API
- `timeit.timeit(stmt, setup, number)`：测量单行或多行代码的执行时间。
- `timeit.repeat(stmt, setup, repeat, number)`：重复多次测量，返回一个时间列表。

### 4.2 示例：测试列表推导式与 `map` 的性能
```python
import timeit

# 测试列表推导式
list_comp_time = timeit.timeit(
    stmt="[x**2 for x in range(1000)]",
    number=10000
)

# 测试 map 函数
map_time = timeit.timeit(
    stmt="list(map(lambda x: x**2, range(1000)))",
    number=10000
)

print(f"列表推导式耗时: {list_comp_time:.4f} 秒")
print(f"map 函数耗时: {map_time:.4f} 秒")
```

### 4.3 命令行快捷用法

`timeit` 模块支持直接在终端中使用，非常适合快速验证：

```bash
# 基本用法（默认执行 1,000,000 次）
python -m timeit "[x**2 for x in range(1000)]"

# 指定执行次数
python -m timeit -n 5000 "[x**2 for x in range(1000)]"

# 使用 -s 指定 setup 初始化代码
python -m timeit -s "import math" "math.sqrt(12345)"

# 比较多行代码
python -m timeit -s "data = list(range(1000))" "sorted(data)"
```

## 5. 三大模块核心区别与对比

| 对比维度 | `time` 模块 | `datetime` 模块 | `timeit` 模块 |
| :--- | :--- | :--- | :--- |
| **主要定位** | 系统底层时钟接口、时间戳转换、休眠控制 | 业务逻辑开发、日期计算、时区处理、格式化解析 | 微观代码性能评估、消除系统背景噪声 |
| **主要类型** | `float` (时间戳), `struct_time` | `date`, `time`, `datetime`, `timedelta`, `timezone` | 无特定对象，返回浮点秒数 |
| **时区支持** | 仅通过本地时间与 UTC 转换支持，无对象级时区 | **完善**，提供 `tzinfo` 及 `timezone` 支持 | 无时区概念 |
| **高精度计时** | 支持，使用 `time.perf_counter()` | 精度较低，不建议用于微秒级耗时统计 | **极高精度**，自带 Setup 初始化与多次循环运行 |
| **主要使用场景**| 系统调用、延时休眠、高精度单次计时 | 数据库时间映射、Token 过期计算、定时任务触发时间 | 算法效率比拼、底层函数重构性能度量 |

## 6. 时区进阶与第三方时间库

Python 原生 `datetime` 模块的时区处理曾令人头疼，但 Python 3.9 起引入了标准库 `zoneinfo`，大幅改善了这一状况。对于更高级的需求，`arrow` 和 `pendulum` 等第三方库则提供了更优雅的 API。

### 6.1 `zoneinfo` 模块（Python 3.9+ 标准库）
Python 3.9 新增的 `zoneinfo` 模块直接支持 IANA 时区数据库，**无需安装任何第三方依赖**即可进行精确的时区操作：

```python
from datetime import datetime
from zoneinfo import ZoneInfo

# 获取带时区的当前时间
dt_shanghai = datetime.now(ZoneInfo("Asia/Shanghai"))
print(f"上海时间: {dt_shanghai}")

# 跨时区转换
dt_newyork = dt_shanghai.astimezone(ZoneInfo("America/New_York"))
print(f"纽约时间: {dt_newyork}")

# 东京时间
dt_tokyo = dt_shanghai.astimezone(ZoneInfo("Asia/Tokyo"))
print(f"东京时间: {dt_tokyo}")
```

> **选择建议**：如果你的项目只需要基本的时区转换，优先使用标准库 `zoneinfo`；如果需要人性化展示或更复杂的日期操作，再考虑第三方库。

### 6.2 `arrow` 模块
- **设计初衷**：更人性化的日期时间操作。
- **优点**：
  - API 极其简洁直观，链式调用。
  - 人性化时间展示（如 `humanize()` 返回 "2 hours ago" 或 "2小时前"）。
  - 内置了对绝大多数常见字符串格式的智能解析。
- **示例**：
```python
import arrow

# 获取当前时间并转化为本地时间
now = arrow.now('Asia/Shanghai')
# 时间推移与人性化输出
past = now.shift(hours=-3)
print(past.humanize(locale='zh-cn'))  # 输出: 3小时前
```

### 6.3 `pendulum` 模块
- **设计初衷**：旨在成为 `datetime` 的完美替代品，彻底重构时区处理和精度。
- **优点**：
  - 继承自 Python 原生 `datetime`，可以直接传入任何期望 `datetime` 对象的标准 API 中（Drop-in 替代品）。
  - 时区处理严格遵循 IANA 时区数据库，极度准确，不需要像 `datetime` 一样手动计算偏移。
  - 精准支持 `Period`（时间段，比如某人生日到今天相隔的完整岁月天数）。
- **示例**：
```python
import pendulum

# 优雅的时区初始化
dt = pendulum.now('Europe/Paris')
print(dt.timezone_name)  # Europe/Paris

# 精确的跨时区转换
dt_sh = dt.in_timezone('Asia/Shanghai')
print(dt_sh.to_datetime_string())
```

## 7. 实际项目使用场景与代码实战

### 场景一：日志记录与数据库存储最佳实践
在分布式系统或 Web 接口中，存储时间时**必须**存为 UTC 时间或带时区的绝对时间，展示时再转换为本地时间。

```python
from datetime import datetime, timezone

def generate_log_meta():
    """生成标准格式日志元数据"""
    # 存入数据库：永远使用 UTC 时间且带有时区标记 (Aware)
    utc_now = datetime.now(timezone.utc)
    
    # 格式化输出为 ISO 8601 标准字符串，便于第三方日志系统分析
    log_format = utc_now.isoformat()
    return {
        "timestamp_utc": log_format,
        "created_at_db": utc_now
    }

print(generate_log_meta())
```

### 场景二：Token 过期与促销倒计时计算
利用 `timedelta` 自动计算未来或过去的某一时间点，并判断当前是否超时。

```python
from datetime import datetime, timezone, timedelta

def generate_jwt_expiration(expire_minutes=30):
    """计算 Token 过期时间点"""
    now = datetime.now(timezone.utc)
    expire_at = now + timedelta(minutes=expire_minutes)
    return expire_at

def is_token_expired(expire_at):
    """判断 Token 是否已过期"""
    # 必须保持同为 Aware datetime 比较，否则会抛出 TypeError
    return datetime.now(timezone.utc) > expire_at

token_expire_time = generate_jwt_expiration()
print(f"Token 将在 {token_expire_time} 过期")
print(f"是否已过期: {is_token_expired(token_expire_time)}")
```

### 场景三：跨国业务中的时区转换
从外部 API 拿到了带有特定时区的字符串时间，需要转成本地时区时间。

```python
from datetime import datetime, timezone, timedelta

# 1. 解析美国纽约时间的字符串（EST 标准时间 UTC-5，夏令时 EDT 为 UTC-4）
ny_time_str = "2026-06-30 08:30:00 -0500"
# %z 可以解析 -0500 或 +0800 格式的时区偏移
ny_dt = datetime.strptime(ny_time_str, "%Y-%m-%d %H:%M:%S %z")
print(f"纽约时间 (Aware): {ny_dt}")

# 2. 将其转换为北京时间 (UTC+8)
tz_beijing = timezone(timedelta(hours=8))
beijing_dt = ny_dt.astimezone(tz_beijing)
print(f"对应的北京时间: {beijing_dt}")
```

### 场景四：优雅的代码执行时间耗时分析
在开发中，若要快速诊断一段逻辑的耗时情况，`time.perf_counter()` 是最佳选择，它提供了系统级的最高分辨率时钟。

```python
import time

def process_large_data():
    # 模拟数据处理耗时
    time.sleep(0.8)

# 获取高精度起点
start_time = time.perf_counter()

process_large_data()

# 计算耗时
end_time = time.perf_counter()
execution_time = end_time - start_time
print(f"数据处理耗时: {execution_time:.6f} 秒")
```

## 8. 常见踩坑点与最佳实践

### 🚨 坑一：混合 Naive 与 Aware 对象进行计算或比较
```python
from datetime import datetime, timezone

t1 = datetime.now() # Naive
t2 = datetime.now(timezone.utc) # Aware

# 报错：TypeError: can't compare offset-naive and offset-aware datetimes
try:
    if t1 > t2:
        pass
except TypeError as e:
    print(f"【报错演示】: {e}")
```
- **最佳实践**：在项目入口处统一使用 `datetime.now(timezone.utc)` 产出 aware 时间，或者在比较前通过 `dt.replace(tzinfo=None)` 进行降维，但最推荐的做法是**全流程维持 Aware 状态**。

### 🚨 坑二：使用 `time.time()` 进行性能测试
`time.time()` 返回的是系统挂钟时间（Wall Clock Time），它会受用户修改系统时间、NTP 时间同步等外部因素干扰，甚至可能出现"时光倒流"现象。
- **最佳实践**：基准测试用 `timeit` 模块，单次代码块耗时统计使用 `time.perf_counter()`。

### 🚨 坑三：解析字符串时月份与分钟的大小写混淆
在 `strftime` 和 `strptime` 中，`%m` 表示月份 (Month, 01-12)，而 `%M` 表示分钟 (Minute, 00-59)。
- **最佳实践**：牢记 `%m` (month) 与 `%M` (Minute) 的区别。例如：`"%Y-%m-%d %H:%M:%S"`。参见本文 **2.6 节格式化符号速查表**。

### 🚨 坑四：使用已弃用的 `datetime.utcnow()`
从 Python 3.12 起，`datetime.utcnow()` 和 `datetime.utcfromtimestamp()` 已被标记为 **deprecated**，因为它们返回的是 Naive 对象，极易引发时区混乱。

```python
from datetime import datetime, timezone

# ❌ 已弃用 (Python 3.12+)，返回 Naive 对象
```

## 9. 扩展：`calendar` 模块简介

`calendar` 模块与日期时间紧密相关，主要用于日历生成和日期判断：

```python
import calendar

# 判断闰年
print(f"2026 是闰年吗？{calendar.isleap(2026)}")  # False
print(f"2028 是闰年吗？{calendar.isleap(2028)}")  # True

# 获取某月的天数（返回：该月第一天是星期几，该月总天数）
weekday, days = calendar.monthrange(2026, 2)
print(f"2026年2月有 {days} 天")  # 28

# 打印某月日历
calendar.prmonth(2026, 7)
```
