## 第六章 事务与并发控制（后端核心思维）

6.1 事务基础
- 事务的 ACID 特性详解
- 事务的生命周期：BEGIN → COMMIT / ROLLBACK
- 自动提交（Autocommit）模式
- 保存点（SAVEPOINT）：部分回滚

6.2 隔离级别
- 四种隔离级别：Read Uncommitted / Read Committed / Repeatable Read / Serializable
- 脏读、不可重复读、幻读的概念与复现
- MySQL 默认 Repeatable Read（Next-Key Lock 解决幻读）
- PostgreSQL 默认 Read Committed
- 两数据库隔离级别实现的底层差异

6.3 锁机制
- 共享锁（S Lock）vs 排他锁（X Lock）
- 表锁 vs 行锁
- 意向锁、间隙锁（Gap Lock）、临键锁（Next-Key Lock）
- 死锁的产生与排查：两个事务互相等待
- 死锁的预防策略：固定加锁顺序、缩短事务、降低隔离级别

6.4 MVCC（多版本并发控制）
- MVCC 的核心思想：读写不互相阻塞
- MySQL InnoDB 的 MVCC 实现：Undo Log + Read View
- PostgreSQL 的 MVCC 实现：元组头部 xmin/xmax + 旧版本存储
- 两者 MVCC 实现的关键差异与性能影响

6.5 乐观锁与悲观锁
- 悲观锁：SELECT ... FOR UPDATE
- 乐观锁：version 字段 + CAS 思想
- 适用场景对比：高并发扣减库存 vs 低冲突场景
- 数据库锁的局限性：单机锁无法跨服务/跨节点
- 分布式锁的引入：Redis SETNX / Redlock 算法（详见第九章）
- 实战：秒杀场景的库存扣减方案（数据库悲观锁 vs 乐观锁 vs Redis 分布式锁对比）

6.6 事务实战场景
- 转账场景：余额扣减 + 记录流水的事务设计
- 订单创建：扣库存 + 创建订单 + 生成支付单的原子性保障
- 批量操作：大批量数据更新的事务控制
- 分布式事务初探：两阶段提交（2PC）、Saga 模式、最终一致性
- 分布式锁与事务的配合：Redis 锁保护数据库操作的经典模式

## 第九章 Redis 核心与锁机制

9.1 Redis 基础认知
- Redis 是什么：内存数据库 vs 磁盘数据库的本质区别
- 为什么后端离不开 Redis：数据库的"好搭档"
- 前端类比理解：Redis 像浏览器内存缓存，MySQL 像 IndexedDB
- Redis 单线程模型与 IO 多路复用（为什么单线程还这么快）
- Redis vs Memcached：功能差异与选型

9.2 Redis 安装与基础操作
- Windows 环境安装 Redis（WSL2 / Docker 方式）
- redis-cli 命令行工具基础
- Python redis-py / aioredis 驱动安装与连接

9.3 Redis 数据结构与应用场景
- String：缓存对象、计数器（点赞数/浏览量）、分布式锁
- Hash：对象存储（用户信息缓存）、部分更新
- List：消息队列（LPUSH/RPOP）、最新列表
- Set：标签集合、共同好友、去重
- ZSet（Sorted Set）：排行榜、延迟队列
- Stream：消息队列（比 List 更可靠的方案）
- Bitmap：签到打卡、用户在线状态
- HyperLogLog：UV 统计（基数估算）
- GEO：地理位置（附近的人/店铺）

9.4 Redis 持久化
- RDB（快照）：定时全量备份，恢复快但可能丢数据
- AOF（追加日志）：实时记录操作，数据安全但文件大
- RDB + AOF 混合持久化（Redis 4.0+）
- 持久化对性能的影响
- 开发环境与生产环境的持久化策略选择

9.5 Redis 过期策略与内存管理
- 过期策略：定期删除 + 惰性删除
- 内存淘汰策略：noeviction / allkeys-lru / volatile-lru / allkeys-lfu 等 8 种
- 生产环境如何选择淘汰策略
- 内存监控与容量规划

9.6 Redis 锁机制（核心重点）
- 为什么需要分布式锁：多服务实例共享资源互斥
- 单机锁 vs 分布式锁：synchronized / threading.Lock 的局限性
- Redis 实现分布式锁的演进：
  - v1：SETNX + EXPIRE（两个命令非原子性，有死锁风险）
  - v2：SET key value NX EX（原子性加锁，解决了 v1 的问题）
  - v3：value 存唯一标识 + Lua 脚本删锁（防止误删别人的锁）
  - v4：Redlock 算法（多节点加锁，防止单点故障）
- 锁的续期问题：看门狗机制（Redisson 的 watchdog）
- 锁的可重入性实现（Hash 结构记录重入次数）
- Redis 分布式锁 vs ZooKeeper 分布式锁 vs etcd 分布式锁对比
- 分布式锁的常见误区与坑：
  - 锁过期但业务未完成 → 看门狗续期
  - 主从切换丢锁 → Redlock 算法
  - 锁竞争激烈导致性能瓶颈 → 分段锁（库存分桶）

9.7 数据库锁 vs Redis 锁对比
- 数据库行锁（SELECT FOR UPDATE）：强一致性，但性能差、不跨实例
- 数据库乐观锁（version 字段）：无锁竞争，但冲突时重试开销大
- Redis 分布式锁：高性能、可跨实例，但不是绝对可靠（极端情况丢锁）
- 三种锁的适用场景决策树：
  - 单服务 + 低并发 → 数据库行锁
  - 单服务 + 中高并发 → 数据库乐观锁
  - 多服务 + 高并发 → Redis 分布式锁
  - 强一致性要求极高 → ZooKeeper / etcd
- 实战对比：同一个秒杀场景的三种锁实现与性能测试

9.8 Redis 缓存模式
- Cache-Aside（旁路缓存）：最常用的缓存策略
- Read-Through / Write-Through / Write-Behind 模式
- 缓存与数据库的一致性问题：
  - 先更新数据库再删缓存（推荐方案）
  - 先删缓存再更新数据库（并发问题）
  - 延迟双删策略
  - Canal 监听 binlog 异步刷缓存
- 缓存穿透：查询不存在的数据 → 布隆过滤器 / 空值缓存
- 缓存击穿：热点 key 过期 → 互斥锁 / 永不过期
- 缓存雪崩：大量 key 同时过期 → 随机过期时间 / 多级缓存
- 实战：商品详情页的缓存设计

9.9 Python 操作 Redis 实战
- redis-py 同步客户端：连接、基本操作、管道（pipeline）
- aioredis / redis-py 异步客户端：配合 asyncio / FastAPI
- 连接池管理：ConnectionPool 的配置与最佳实践
- Lua 脚本执行：EVAL / EVALSHA 的使用场景
- 实战：用 Python + Redis 实现分布式锁工具类
- 实战：用 Python + Redis 实现缓存装饰器（@cache装饰器）

9.10 Redis + 数据库经典配合场景
- 缓存层：热点数据缓存减轻数据库压力
