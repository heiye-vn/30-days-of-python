## 10.1 用户认证与权限系统

### 10.1.1 核心需求分析

用户认证与权限系统是几乎所有后端应用的基础设施。一个完善的认证系统需要解决以下问题:

- **用户身份标识**:用户名、邮箱、手机号均可作为登录凭证,且需保证唯一性
- **密码安全**:绝不存储明文密码,必须使用 bcrypt/argon2 等算法进行哈希
- **登录状态管理**:JWT Token 的签发、存储与吊销
- **权限控制**:谁能访问哪些资源,RBAC(基于角色的访问控制)是业界标准方案
- **第三方登录**:GitHub、Google 等 OAuth2 登录的接入

### 10.1.2 用户表设计

用户表是整个系统的核心。设计要点如下:

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT, 主键 | 自增或雪花 ID |
| username | VARCHAR(50) | 用户名,唯一索引 |
| email | VARCHAR(255) | 邮箱,唯一索引,可空(支持手机号注册) |
| phone | VARCHAR(20) | 手机号,唯一索引,可空 |
| password_hash | VARCHAR(255) | 密码哈希值,绝不存明文 |
| status | TINYINT/SMALLINT | 账号状态:0=禁用,1=正常,2=待激活 |
| last_login_at | TIMESTAMP | 最后登录时间 |
| last_login_ip | VARCHAR(45) | 最后登录 IP(IPv6 最长 45 字符) |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

**设计决策说明**:

1. email 和 phone 都设为可空(NULL),但通过部分唯一索引保证"非空时唯一"。MySQL 没有原生的部分索引,但可以利用空值不参与唯一约束的特性(多个 NULL 值不冲突)。
2. password_hash 字段长度设为 255,因为 bcrypt 哈希为 60 字符,argon2 可能更长,预留空间。
3. status 使用整数而非字符串,存储和索引效率更高。

```sql
-- 用户主表
CREATE TABLE `users` (
    `id`              BIGINT       NOT NULL AUTO_INCREMENT,
    `username`        VARCHAR(50)  NOT NULL COMMENT '用户名',
    `email`           VARCHAR(255) DEFAULT NULL COMMENT '邮箱(可空,但非空时唯一)',
    `phone`           VARCHAR(20)  DEFAULT NULL COMMENT '手机号(可空,但非空时唯一)',
    `password_hash`   VARCHAR(255) NOT NULL COMMENT '密码哈希(bcrypt/argon2)',
    `status`          TINYINT      NOT NULL DEFAULT 1 COMMENT '0=禁用,1=正常,2=待激活',
    `last_login_at`   TIMESTAMP    NULL DEFAULT NULL COMMENT '最后登录时间',
    `last_login_ip`   VARCHAR(45)  DEFAULT NULL COMMENT '最后登录IP',
    `created_at`      TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`      TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_username` (`username`),
    UNIQUE KEY `uk_email` (`email`),
    UNIQUE KEY `uk_phone` (`phone`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 角色表
CREATE TABLE `roles` (
    `id`          INT          NOT NULL AUTO_INCREMENT,
    `code`        VARCHAR(50)  NOT NULL COMMENT '角色编码(如 admin,user,editor)',
    `name`        VARCHAR(100) NOT NULL COMMENT '角色显示名',
    `description` VARCHAR(255) DEFAULT NULL,
    `created_at`  TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`  TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_role_code` (`code`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 权限表
CREATE TABLE `permissions` (
    `id`          INT          NOT NULL AUTO_INCREMENT,
    `code`        VARCHAR(100) NOT NULL COMMENT '权限编码(如 article:create,user:delete)',
    `name`        VARCHAR(100) NOT NULL COMMENT '权限显示名',
    `resource`    VARCHAR(50)  NOT NULL COMMENT '资源类型(article/user/order等)',
    `action`      VARCHAR(20)  NOT NULL COMMENT '操作类型(create/read/update/delete)',
    `created_at`  TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_perm_code` (`code`),
    KEY `idx_perm_resource` (`resource`, `action`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 用户-角色关联表(多对多)
CREATE TABLE `user_roles` (
    `user_id`     BIGINT    NOT NULL,
    `role_id`     INT       NOT NULL,

    `granted_by`  BIGINT    DEFAULT NULL COMMENT '授权人ID',
    PRIMARY KEY (`user_id`, `role_id`),
    KEY `idx_user_roles_role` (`role_id`),
    CONSTRAINT `fk_user_roles_user` FOREIGN KEY (`user_id`) REFERENCES `users` (`id`) ON DELETE CASCADE,
    CONSTRAINT `fk_user_roles_role` FOREIGN KEY (`role_id`) REFERENCES `roles` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 角色-权限关联表(多对多)
CREATE TABLE `role_permissions` (
    `role_id`       INT       NOT NULL,
    `permission_id` INT       NOT NULL,
    `created_at`    TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`role_id`, `permission_id`),
    KEY `idx_role_perm_perm` (`permission_id`),
    CONSTRAINT `fk_role_perm_role` FOREIGN KEY (`role_id`) REFERENCES `roles` (`id`) ON DELETE CASCADE,
    CONSTRAINT `fk_role_perm_perm` FOREIGN KEY (`permission_id`) REFERENCES `permissions` (`id`) ON DELETE CASCADE

-- OAuth2 第三方登录账号表
CREATE TABLE `oauth_accounts` (
    `id`              BIGINT       NOT NULL AUTO_INCREMENT,
    `user_id`         BIGINT       NOT NULL COMMENT '关联的本地用户ID',
    `provider`        VARCHAR(20)  NOT NULL COMMENT '提供方:github,google,wechat等',
    `provider_uid`    VARCHAR(100) NOT NULL COMMENT '提供方返回的用户唯一ID',
    `access_token`    VARCHAR(512) DEFAULT NULL COMMENT '访问令牌(加密存储)',
    `refresh_token`   VARCHAR(512) DEFAULT NULL COMMENT '刷新令牌(加密存储)',
    `token_expires_at` TIMESTAMP   DEFAULT NULL,
    `provider_data`   JSON         DEFAULT NULL COMMENT '提供方返回的原始用户信息',
    `created_at`      TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`      TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_provider_uid` (`provider`, `provider_uid`),
    KEY `idx_oauth_user` (`user_id`),
    CONSTRAINT `fk_oauth_user` FOREIGN KEY (`user_id`) REFERENCES `users` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 10.1.4 PostgreSQL 建表 SQL

```sql
-- ============================================================
-- PostgreSQL 14+ 用户认证与权限系统建表
-- ============================================================

-- 用户主表
CREATE TABLE users (
    id              BIGSERIAL    PRIMARY KEY,
    username        VARCHAR(50)  NOT NULL,
    email           VARCHAR(255) UNIQUE,  -- NULL 值默认允许多个

);

-- email 部分唯一索引:仅对非空 email 做唯一约束(更严格)
CREATE UNIQUE INDEX uk_users_email_nonnull ON users (email) WHERE email IS NOT NULL;
CREATE UNIQUE INDEX uk_users_phone_nonnull ON users (phone) WHERE phone IS NOT NULL;

-- 角色表
CREATE TABLE roles (
    id          SERIAL       PRIMARY KEY,
    code        VARCHAR(50)  NOT NULL UNIQUE,
    name        VARCHAR(100) NOT NULL,
    description VARCHAR(255),
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

-- 权限表
CREATE TABLE permissions (
    id          SERIAL       PRIMARY KEY,
    code        VARCHAR(100) NOT NULL UNIQUE,
    name        VARCHAR(100) NOT NULL,
    resource    VARCHAR(50)  NOT NULL,
    action      VARCHAR(20)  NOT NULL,
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_perm_resource_action ON permissions (resource, action);

-- 用户-角色关联表
CREATE TABLE user_roles (
    user_id    BIGINT      NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    role_id    INT         NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
    granted_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    granted_by BIGINT      REFERENCES users(id),
    PRIMARY KEY (user_id, role_id)
);

CREATE INDEX idx_user_roles_role ON user_roles (role_id);

-- 角色-权限关联表
CREATE TABLE role_permissions (
    role_id       INT         NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
    permission_id INT         NOT NULL REFERENCES permissions(id) ON DELETE CASCADE,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (role_id, permission_id)
);

CREATE INDEX idx_role_perm_perm ON role_permissions (permission_id);

-- OAuth2 第三方登录表
CREATE TABLE oauth_accounts (
    id               BIGSERIAL    PRIMARY KEY,
    user_id          BIGINT       NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    provider         VARCHAR(20)  NOT NULL,
    provider_uid     VARCHAR(100) NOT NULL,
    access_token     TEXT,        -- 使用 TEXT 存储加密后的长令牌
    refresh_token    TEXT,
    token_expires_at TIMESTAMPTZ,
    provider_data    JSONB,       -- PostgreSQL JSONB 支持 GIN 索引
    created_at       TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

CREATE UNIQUE INDEX uk_oauth_provider_uid ON oauth_accounts (provider, provider_uid);
CREATE INDEX idx_oauth_user ON oauth_accounts (user_id);
```

### 10.1.5 JWT Token 存储方案对比

JWT 是无状态的,本身不需要服务端存储。但在实际业务中,我们通常需要存储 Token 的原因有两个:**主动吊销**(用户登出、修改密码后让旧 Token 失效)和**单设备登录限制**。

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 纯 JWT 无存储 | 性能最好,无额外依赖 | 无法主动吊销 | 对安全性要求不高的场景 |
| Redis 存白名单 | 高性能,TTL 自动过期 | 需要 Redis | 大多数 Web 应用(推荐) |
| 数据库存 Token | 可审计,可复杂查询 | 性能差,需定期清理 | 对审计要求严格的场景 |

**推荐方案**:JWT + Redis 白名单。签发 JWT 后,将其 jti(JWT ID)存入 Redis 并设置 TTL 等于 JWT 过期时间。每次请求校验 JWT 时,同时检查 Redis 中该 jti 是否存在。

### 10.1.6 Python 代码示例

```python
"""
用户认证与权限系统 - Python 代码示例
依赖: pip install bcrypt sqlalchemy psycopg2-binary pymysql redis
"""
import bcrypt
import secrets
import time
import json
from datetime import datetime, timedelta
import redis
from sqlalchemy import create_engine, text
from sqlalchemy.orm import sessionmaker

# ============================================================
# 配置初始化
# ============================================================
# PostgreSQL 连接
DB_URL = "postgresql+psycopg2://user:pass@localhost:5432/myapp"
engine = create_engine(DB_URL, pool_size=10, max_overflow=20, pool_pre_ping=True)
Session = sessionmaker(bind=engine)

# Redis 连接(用于 JWT 白名单)
rds = redis.Redis(host="localhost", port=6379, db=0, decode_responses=True)

# JWT 密钥(实际项目中应从环境变量读取)
JWT_SECRET = "your-super-secret-key-change-in-production"
JWT_EXPIRE_SECONDS = 7200  # 2 小时


# ============================================================
# 工具函数:密码哈希与校验
# ============================================================
def hash_password(plain_password: str) -> str:
    """使用 bcrypt 对密码进行哈希,返回字符串"""
    salt = bcrypt.gensalt(rounds=12)
    hashed = bcrypt.hashpw(plain_password.encode("utf-8"), salt)
    return hashed.decode("utf-8")

def verify_password(plain_password: str, hashed_password: str) -> bool:
    """验证明文密码与哈希是否匹配"""
    return bcrypt.checkpw(
        plain_password.encode("utf-8"),
        hashed_password.encode("utf-8")
    )

def generate_jwt(user_id: int, username: str) -> dict:
    """
    生成简单的 JWT(生产环境建议用 PyJWT 库)
    返回: {"token": "...", "jti": "...", "expires_at": ...}
    这里用简化版本演示,实际应使用 PyJWT 库
    """
    import hashlib
    jti = secrets.token_hex(16)
    expires_at = int(time.time()) + JWT_EXPIRE_SECONDS

    # 简化的 JWT 构造(生产环境请使用 PyJWT)
    header = json.dumps({"alg": "HS256", "typ": "JWT"}, separators=(",", ":"))
    payload = json.dumps({
        "user_id": user_id,
        "username": username,
        "jti": jti,
        "exp": expires_at
    }, separators=(",", ":"))

    import base64
    b64_header = base64.urlsafe_b64encode(header.encode()).rstrip(b"=").decode()
    b64_payload = base64.urlsafe_b64encode(payload.encode()).rstrip(b"=").decode()

    signing_input = f"{b64_header}.{b64_payload}"
    signature = hmac_sha256(JWT_SECRET, signing_input)
    token = f"{signing_input}.{signature}"

    # 存入 Redis 白名单,设置 TTL
    rds.setex(f"jwt:{jti}", JWT_EXPIRE_SECONDS, str(user_id))

    return {"token": token, "jti": jti, "expires_at": expires_at}

def hmac_sha256(key: str, msg: str) -> str:
    import hmac
    import hashlib
    return base64.urlsafe_b64encode(
        hmac.new(key.encode(), msg.encode(), hashlib.sha256).digest()
    ).rstrip(b"=").decode()


# ============================================================
# 用户注册
# ============================================================
def register_user(username: str, email: str, password: str) -> dict:
    """
    用户注册:
    1. 检查用户名/邮箱是否已存在
    2. 密码哈希存储
    3. 分配默认角色(普通用户)
    """
    session = Session()
    try:
        # 检查用户名唯一性
        existing = session.execute(
            text("SELECT id FROM users WHERE username = :u OR email = :e"),
            {"u": username, "e": email}
        ).fetchone()

        if existing:
            return {"success": False, "error": "username_or_email_exists"}

        # 密码哈希
        pw_hash = hash_password(password)

        # 插入用户记录
        result = session.execute(
            text("""
                INSERT INTO users (username, email, password_hash, status)
                VALUES (:username, :email, :pw_hash, 1)
                RETURNING id
            """),
            {"username": username, "email": email, "pw_hash": pw_hash}
        )
        user_id = result.fetchone()[0]

        # 分配默认角色(假设 role_id=2 是普通用户)
        session.execute(
            text("""
                INSERT INTO user_roles (user_id, role_id)
                SELECT :uid, id FROM roles WHERE code = 'user'
                ON CONFLICT DO NOTHING
            """),
            {"uid": user_id}
        )

        session.commit()
        return {"success": True, "user_id": user_id}

    except Exception as e:
        session.rollback()
        return {"success": False, "error": str(e)}
    finally:
        session.close()


# ============================================================
# 用户登录验证
# ============================================================
def login_user(login_key: str, password: str) -> dict:
    """
    用户登录:
    login_key 可以是用户名、邮箱或手机号
    1. 查询用户记录
    2. 校验密码
    3. 检查账号状态
    4. 更新登录时间/IP
    5. 签发 JWT
    """
    session = Session()
    try:
        row = session.execute(
            text("""
                SELECT id, username, password_hash, status
                FROM users
                WHERE username = :key OR email = :key OR phone = :key
                LIMIT 1
            """),
            {"key": login_key}
        ).fetchone()

        if not row:
            return {"success": False, "error": "user_not_found"}

        user_id, username, pw_hash, status = row

        # 校验密码
        if not verify_password(password, pw_hash):
            return {"success": False, "error": "invalid_password"}

        # 检查账号状态
        if status == 0:
            return {"success": False, "error": "account_disabled"}
        elif status == 2:
            return {"success": False, "error": "account_not_activated"}

        # 更新登录时间
        session.execute(
            text("""
                UPDATE users
                SET last_login_at = NOW(), last_login_ip = :ip
                WHERE id = :uid
            """),
            {"ip": "127.0.0.1", "uid": user_id}
        )
        session.commit()

        # 签发 JWT
        token_info = generate_jwt(user_id, username)
        return {
            "success": True,
            "token": token_info["token"],
            "user_id": user_id,
            "username": username
        }

    except Exception as e:
        session.rollback()
        return {"success": False, "error": str(e)}
    finally:
        session.close()


# ============================================================
# 权限检查
# ============================================================
def check_permission(user_id: int, permission_code: str) -> bool:
    """
    检查用户是否拥有指定权限
    通过 RBAC 五表关联查询: user -> user_roles -> roles -> role_permissions -> permissions
    """
    session = Session()
    try:
        # 使用 WITH 子查询一次性完成五表关联
        result = session.execute(
            text("""
                SELECT 1
                FROM user_roles ur
                JOIN role_permissions rp ON rp.role_id = ur.role_id
                JOIN permissions p ON p.id = rp.permission_id
                WHERE ur.user_id = :uid AND p.code = :perm
                LIMIT 1
            """),
            {"uid": user_id, "perm": permission_code}
        ).fetchone()

        return result is not None
    finally:
        session.close()


def get_user_permissions(user_id: int) -> list:
    """获取用户的所有权限编码列表(可用于前端按钮级权限控制)"""
    session = Session()
    try:
        rows = session.execute(
            text("""
                SELECT DISTINCT p.code, p.name, p.resource, p.action
                FROM user_roles ur
                JOIN role_permissions rp ON rp.role_id = ur.role_id
                JOIN permissions p ON p.id = rp.permission_id
                WHERE ur.user_id = :uid
                ORDER BY p.resource, p.action
            """),
            {"uid": user_id}
        ).fetchall()

        return [
            {"code": r[0], "name": r[1], "resource": r[2], "action": r[3]}
            for r in rows
        ]
    finally:
        session.close()


def get_user_roles(user_id: int) -> list:
    """获取用户的所有角色"""
    session = Session()
    try:
        rows = session.execute(
            text("""
                SELECT r.id, r.code, r.name
                FROM user_roles ur
                JOIN roles r ON r.id = ur.role_id
                WHERE ur.user_id = :uid
            """),
            {"uid": user_id}
        ).fetchall()
        return [{"id": r[0], "code": r[1], "name": r[2]} for r in rows]
    finally:
        session.close()


# ============================================================
# JWT 吊销(登出)
# ============================================================
def revoke_token(jti: str):
    """从 Redis 白名单中删除 JWT,使其立即失效"""
    rds.delete(f"jwt:{jti}")

def verify_token(jti: str) -> bool:
    """检查 JWT 是否仍在白名单中"""
    return rds.exists(f"jwt:{jti}") > 0


# ============================================================
# OAuth2 第三方登录
# ============================================================
def oauth_login(provider: str, provider_uid: str, user_info: dict) -> dict:
    """
    OAuth2 登录流程:
    1. 查询 oauth_accounts 表,看该第三方账号是否已绑定
    2. 已绑定:直接登录,签发 JWT
    3. 未绑定:创建用户 + 绑定 OAuth 账号 + 签发 JWT
    """
    session = Session()
    try:
        # 查询是否已有绑定
        row = session.execute(
            text("""
                SELECT user_id FROM oauth_accounts
                WHERE provider = :p AND provider_uid = :uid
            """),
            {"p": provider, "uid": provider_uid}
        ).fetchone()

        if row:
            # 已绑定,直接登录
            user_id = row[0]
            session.execute(
                text("UPDATE users SET last_login_at = NOW() WHERE id = :uid"),
                {"uid": user_id}
            )
            session.commit()
        else:
            # 未绑定,创建新用户
            username = f"{provider}_{provider_uid[:8]}"
            result = session.execute(
                text("""
                    INSERT INTO users (username, password_hash, status)
                    VALUES (:u, :pw, 1)
                    RETURNING id
                """),
                {"u": username, "pw": hash_password(secrets.token_hex(32))}
            )
            user_id = result.fetchone()[0]

            # 绑定 OAuth 账号
            session.execute(
                text("""
                    INSERT INTO oauth_accounts
                        (user_id, provider, provider_uid, provider_data)
                    VALUES (:uid, :p, :puid, :pdata)
                """),
                {"uid": user_id, "p": provider, "puid": provider_uid,
                 "pdata": json.dumps(user_info)}
            )

            # 分配默认角色
            session.execute(
                text("""
                    INSERT INTO user_roles (user_id, role_id)
                    SELECT :uid, id FROM roles WHERE code = 'user'
                """),
                {"uid": user_id}
            )
            session.commit()

        token_info = generate_jwt(user_id, username)
        return {"success": True, "token": token_info["token"], "user_id": user_id}

    except Exception as e:
        session.rollback()
        return {"success": False, "error": str(e)}
    finally:
        session.close()
```

### 10.1.7 关键设计总结

1. **密码安全**:永远使用 bcrypt(rounds=12)或 argon2id,绝不使用 MD5/SHA1。
2. **RBAC 五表模型**:users、roles、permissions、user_roles、role_permissions 是标准 RBAC 设计,可覆盖 90% 的权限需求。如果需要更细粒度的数据权限(例如"只能编辑自己创建的文章"),需要额外增加数据权限规则表。
3. **OAuth2 设计**:oauth_accounts 表通过 (provider, provider_uid) 复合唯一键保证一个第三方账号只能绑定一个本地用户。provider_data 使用 JSONB 存储,方便扩展不同提供方返回的不同字段结构。
4. **JWT 吊销**:Redis 白名单方案在性能和灵活性之间取得了平衡。如果对安全性要求极高(如金融系统),可以考虑"数据库黑名单 + Redis 缓存"的方案。

## 10.2 电商商品与订单系统

### 10.2.1 SPU/SKU 模型设计

电商系统中最核心的概念是 SPU(标准化产品单元)和 SKU(库存量单位):

- **SPU**:描述一类商品的公共属性,如"iPhone 15 Pro"——它有颜色、存储容量等规格,但 SPU 本身不直接对应可购买的实体
- **SKU**:SPU 的某个具体规格组合,如"iPhone 15 Pro / 深空黑 / 256GB"——SKU 才是有价格、有库存、可直接下单的实体

**数据模型关系**:

```
SPU (1) ---> (N) SKU
SPU (1) ---> (N) ProductAttribute (规格定义,如"颜色""存储容量")
SKU (1) ---> (N) SKUAttribute (具体规格值,如"深空黑""256GB")
```

### 10.2.2 商品表结构设计

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| spu | 标准产品单元 | name, category_id, brand, status |
| sku | 库存量单位 | spu_id, sku_code, price, stock |
| product_attributes | 商品规格定义 | spu_id, name(如"颜色") |
| sku_attribute_values | SKU 规格值 | sku_id, attribute_id, value(如"红色") |

### 10.2.6 Python 代码示例:下单流程

```python
"""
电商系统 - Python 代码示例
依赖: pip install sqlalchemy psycopg2-binary redis
"""
import time
import uuid
from decimal import Decimal
from sqlalchemy import create_engine, text
from sqlalchemy.orm import sessionmaker
import redis

DB_URL = "postgresql+psycopg2://user:pass@localhost:5432/shop"
engine = create_engine(DB_URL, pool_size=10, max_overflow=20, pool_pre_ping=True)
Session = sessionmaker(bind=engine)
rds = redis.Redis(host="localhost", port=6379, db=0, decode_responses=True)


def generate_order_no() -> str:
    """生成订单号: 日期 + 用户ID后4位 + 随机数"""
    date_str = time.strftime("%Y%m%d%H%M%S", time.localtime())
    random_str = uuid.uuid4().hex[:6].upper()
    return f"ORD{date_str}{random_str}"


def place_order(user_id: int, items: list, address: dict, remark: str = None) -> dict:
    """
    下单流程(乐观锁方案):
    items: [{"sku_id": 123, "quantity": 2}, ...]
    address: {"name": "张三", "phone": "13800000000", "detail": "..."}

    步骤:
    1. 查询 SKU 信息,校验状态和库存
    2. 计算订单金额
    3. 使用乐观锁扣减库存(UPDATE ... WHERE stock >= quantity)
    4. 创建订单主表 + 明细表
    5. 记录状态流转日志
    """
    session = Session()
    try:
        # 订单号
        order_no = generate_order_no()
        total_amount = Decimal("0")
        order_items_data = []

        # 步骤1: 查询所有 SKU,校验
        sku_ids = [item["sku_id"] for item in items]
        skus = session.execute(
            text("""
                SELECT id, spu_id, sku_code, price, stock, locked_stock, status
                FROM sku WHERE id = ANY(:ids) FOR UPDATE
            """),
            {"ids": sku_ids}
        ).fetchall()

        sku_map = {s[0]: s for s in skus}
        for item in items:
            sku = sku_map.get(item["sku_id"])
            if not sku:
                raise ValueError(f"SKU {item['sku_id']} not found")
            if sku[6] != 1:  # status
                raise ValueError(f"SKU {item['sku_id']} not available")

            available = sku[4] - sku[5]  # stock - locked_stock
            if available < item["quantity"]:
                raise ValueError(f"SKU {item['sku_id']} insufficient stock")

            # 获取 SPU 名称(快照)
            spu_row = session.execute(
                text("SELECT name FROM spu WHERE id = :sid"),
                {"sid": sku[1]}
            ).fetchone()
            spu_name = spu_row[0] if spu_row else ""

            # 获取 SKU 规格信息(快照)
            attrs = session.execute(
                text("""
                    SELECT a.name, v.value
                    FROM sku_attribute_values v
                    JOIN product_attributes a ON a.id = v.attribute_id
                    WHERE v.sku_id = :sid
                """),
                {"sid": item["sku_id"]}
            ).fetchall()
            sku_attrs = {a[0]: a[1] for a in attrs}

            price = Decimal(str(sku[3]))
            quantity = item["quantity"]
            subtotal = price * quantity
            total_amount += subtotal

            order_items_data.append({
                "sku_id": item["sku_id"],
                "spu_name": spu_name,
                "sku_attrs": sku_attrs,
                "price": price,
                "quantity": quantity,
                "subtotal": subtotal
            })

        # 步骤2: 创建订单主表
        import json
        session.execute(
            text("""
                INSERT INTO orders
                    (order_no, user_id, total_amount, status,
                     shipping_address, remark, expire_at)
                VALUES (:no, :uid, :total, 0, :addr, :remark, NOW() + INTERVAL '30 minutes')
            """),
            {
                "no": order_no, "uid": user_id,
                "total": total_amount,
                "addr": json.dumps(address),
                "remark": remark
            }
        )

        # 步骤3: 创建订单明细
        for oi in order_items_data:
            session.execute(
                text("""
                    INSERT INTO order_items
                        (order_no, sku_id, spu_name, sku_attrs, price, quantity, subtotal)
                    VALUES (:no, :sid, :sname, :sattrs, :price, :qty, :subtotal)
                """),
                {
                    "no": order_no, "sid": oi["sku_id"],
                    "sname": oi["spu_name"],
                    "sattrs": json.dumps(oi["sku_attrs"]),
                    "price": oi["price"], "qty": oi["quantity"],
                    "subtotal": oi["subtotal"]
                }
            )

        # 步骤4: 乐观锁扣减库存
        for item in items:
            result = session.execute(
                text("""
                    UPDATE sku
                    SET locked_stock = locked_stock + :qty
                    WHERE id = :sid AND (stock - locked_stock) >= :qty
                """),
                {"sid": item["sku_id"], "qty": item["quantity"]}
            )
            if result.rowcount == 0:
                raise ValueError(f"SKU {item['sku_id']} stock changed, please retry")

        # 步骤5: 记录状态流转
        session.execute(
            text("""
                INSERT INTO order_status_log (order_no, from_status, to_status, operator_id)
                VALUES (:no, -1, 0, :uid)
            """),
            {"no": order_no, "uid": user_id}
        )

        session.commit()
        return {"success": True, "order_no": order_no, "total_amount": float(total_amount)}

    except Exception as e:
        session.rollback()
        return {"success": False, "error": str(e)}
    finally:
        session.close()


def handle_payment_callback(order_no: str, transaction_id: str,
                            amount: Decimal, method: str, raw_data: str) -> dict:
    """
    支付回调处理(幂等性设计):
    1. 检查 payment_records 是否已处理该 transaction_id(幂等)
    2. 检查订单状态是否为待支付(防重复处理)
    3. 使用 SELECT ... FOR UPDATE 锁定订单行
    4. 更新订单状态为已支付
    5. 扣减锁定库存,增加销量
    6. 记录支付流水
    """
    session = Session()
    try:
        # 步骤1: 幂等性检查 - 事务号是否已存在
        existing = session.execute(
            text("SELECT id, status FROM payment_records WHERE transaction_id = :tid"),
            {"tid": transaction_id}
        ).fetchone()

        if existing:
            if existing[1] == 1:  # 已成功处理
                return {"success": True, "message": "already_processed"}
            # 之前失败,继续处理

        # 步骤2: 锁定订单行
        order = session.execute(
            text("SELECT order_no, status, total_amount FROM orders WHERE order_no = :no FOR UPDATE"),
            {"no": order_no}
        ).fetchone()

        if not order:
            return {"success": False, "error": "order_not_found"}

        if order[1] != 0:  # status != 待支付
            return {"success": False, "error": f"order_status_invalid: {order[1]}"}

        # 校验金额
        if Decimal(str(order[2])) != amount:
            return {"success": False, "error": "amount_mismatch"}

        # 步骤3: 更新订单状态
        session.execute(
            text("""
                UPDATE orders
                SET status = 1, pay_amount = :amt, payment_method = :method,
                    payment_time = NOW()
                WHERE order_no = :no AND status = 0
            """),
            {"no": order_no, "amt": amount, "method": method}
        )

        # 步骤4: 扣减锁定库存 -> 真实扣减,增加销量
        session.execute(
            text("""
                UPDATE sku
                SET stock = stock - oi.quantity,
                    locked_stock = locked_stock - oi.quantity,
                    sales_count = sales_count + oi.quantity
                FROM order_items oi
                WHERE oi.order_no = :no AND oi.sku_id = sku.id
            """),
            {"no": order_no}
        )

        # 步骤5: 记录状态流转
        session.execute(
            text("""
                INSERT INTO order_status_log (order_no, from_status, to_status, remark)
                VALUES (:no, 0, 1, 'payment_callback')
            """),
            {"no": order_no}
        )

        # 步骤6: 记录支付流水(幂等:如果已存在则更新)
        if existing:
            session.execute(
                text("""
                    UPDATE payment_records
                    SET status = 1, callback_raw = :raw, updated_at = NOW()
                    WHERE transaction_id = :tid
                """),
                {"tid": transaction_id, "raw": raw_data}
            )
        else:
            session.execute(
                text("""
                    INSERT INTO payment_records
                        (order_no, transaction_id, payment_method, amount, status, callback_raw)
                    VALUES (:no, :tid, :method, :amt, 1, :raw)
                """),
                {"no": order_no, "tid": transaction_id,
                 "method": method, "amt": amount, "raw": raw_data}
            )

        session.commit()
        return {"success": True, "order_no": order_no}

    except Exception as e:
        session.rollback()
        return {"success": False, "error": str(e)}
    finally:
        session.close()


def redis_pre_deduct_stock(sku_id: int, quantity: int) -> bool:
    """
    Redis 预扣减库存方案(高并发场景):
    1. 从 Redis 读取当前库存
    2. 使用 Lua 脚本原子扣减(保证原子性)
    3. 扣减成功后,异步同步到数据库
    """
    lua_script = """
        local key = KEYS[1]
        local quantity = tonumber(ARGV[1])
        local current = tonumber(redis.call('GET', key) or '0')
        if current >= quantity then
            redis.call('DECRBY', key, quantity)
            return 1
        else
            return 0
        end
    """
    result = rds.eval(lua_script, 1, f"sku:stock:{sku_id}", quantity)
    return result == 1
```

### 10.2.7 库存扣减方案对比

| 方案 | 实现方式 | 优点 | 缺点 | 适用场景 |
|------|----------|------|------|----------|
| 悲观锁 | SELECT ... FOR UPDATE | 简单直接 | 并发性能差 | 低并发场景 |
| 乐观锁 | UPDATE ... WHERE stock >= qty | 无锁等待,性能好 | 高并发时重试多 | 中等并发(推荐) |
| Redis 预扣减 | Lua 原子操作 | 极高性能 | 需要异步同步 DB | 秒杀/抢购 |

### 10.2.8 关键设计总结

1. **SPU/SKU 分离**:SPU 描述商品公共属性,SKU 负责具体可购买实体。价格、库存都在 SKU 层面。
2. **订单快照**:order_items 中冗余了 spu_name、price、sku_attrs,因为商品信息可能随时变更,但订单历史必须保留下单时刻的信息。
3. **库存分两个字段**:stock(总库存)和 locked_stock(锁定库存)。下单时增加 locked_stock,支付后同时减少 stock 和 locked_stock,取消订单时减少 locked_stock。这样"可用库存 = stock - locked_stock"。
4. **支付回调幂等**:通过 payment_records 表的 transaction_id 唯一约束 + 订单状态校验,保证回调重复发送时不会重复处理。
5. **订单超时取消**:expire_at 字段 + 定时任务扫描,超时未支付的订单自动取消并释放锁定库存。

## 10.3 内容管理系统(CMS)

### 10.3.1 核心需求分析

内容管理系统是 Web 开发中最常见的业务场景之一。核心模块包括:

- **文章管理**:标题、正文、摘要、封面图、状态(草稿/发布/下架)
- **分类体系**:支持树形分类(无限层级)
- **标签系统**:多对多关系,一篇文章可有多个标签
- **评论系统**:支持无限层级嵌套回复
- **全文搜索**:对文章标题和正文进行关键词搜索

### 10.3.2 树形分类方案对比

| 方案 | 表结构 | 查询子树 | 移动节点 | 适用场景 |
|------|--------|----------|----------|----------|
| 邻接表 | parent_id | 递归查询(慢) | 简单 | 分类层级少(2-3层) |
| 路径枚举 | path(如 /1/2/3/) | LIKE 前缀匹配 | 需更新子树路径 | 读多写少 |
| 嵌套集 | lft, rgt | BETWEEN 查询 | 复杂(需大量更新) | 极少修改的树 |
| 闭包表 | 单独的关系表 | JOIN 查询 | 简单 | 需要灵活查询 |

**推荐**:分类系统使用**邻接表 + PostgreSQL 递归 CTE**或**路径枚举**方案。下面以路径枚举为例,因为它查询效率高且实现简单。

### 10.3.3 评论系统设计方案

评论无限层级嵌套有两种主流方案:

1. **邻接表 + 递归查询**:parent_id 指向父评论,使用递归 CTE 查询整棵评论树
2. **路径枚举**:存储 path 字段(如 1/4/7/),按 path 排序即可得到树形结构

推荐使用**路径枚举**方案:查询时按 path 排序,一次查询即可得到完整的树形结构,前端只需根据层级缩进渲染。

```python
"""
内容管理系统 - Python 代码示例
依赖: pip install sqlalchemy psycopg2-binary
"""
import json
from sqlalchemy import create_engine, text
from sqlalchemy.orm import sessionmaker

DB_URL = "postgresql+psycopg2://user:pass@localhost:5432/cms"
engine = create_engine(DB_URL, pool_size=10, max_pre_ping=True)
Session = sessionmaker(bind=engine)


def publish_article(title: str, content: str, category_id: int,
                    author_id: int, summary: str = None,
                    cover_image: str = None, tags: list = None) -> dict:
    """
    发布文章:
    1. 插入文章记录
    2. 处理标签(新增或关联)
    3. 更新标签使用计数
    """
    session = Session()
    try:
        # 插入文章
        result = session.execute(
            text("""
                INSERT INTO articles
                    (title, summary, content, cover_image, category_id,
                     author_id, status, published_at)
                VALUES (:title, :summary, :content, :cover, :cat,
                        :author, 1, NOW())
                RETURNING id
            """),
            {
                "title": title, "summary": summary, "content": content,
                "cover": cover_image, "cat": category_id, "author": author_id
            }
        )
        article_id = result.fetchone()[0]

        # 处理标签
        if tags:
            for tag_name in tags:
                slug = tag_name.lower().replace(" ", "-")
                # 插入标签(如不存在则创建),返回 id
                tag_result = session.execute(
                    text("""
                        INSERT INTO tags (name, slug, usage_count)
                        VALUES (:name, :slug, 0)
                        ON CONFLICT (slug) DO UPDATE SET name = tags.name
                        RETURNING id
                    """),
                    {"name": tag_name, "slug": slug}
                )
                tag_id = tag_result.fetchone()[0]

                # 关联文章-标签
                session.execute(
                    text("""
                        INSERT INTO article_tags (article_id, tag_id)
                        VALUES (:aid, :tid)
                        ON CONFLICT DO NOTHING
                    """),
                    {"aid": article_id, "tid": tag_id}
                )

                # 更新标签使用计数
                session.execute(
                    text("UPDATE tags SET usage_count = usage_count + 1 WHERE id = :tid"),
                    {"tid": tag_id}
                )

        session.commit()
        return {"success": True, "article_id": article_id}

    except Exception as e:
        session.rollback()
        return {"success": False, "error": str(e)}
    finally:
        session.close()


def get_comment_tree(article_id: int, page: int = 1, page_size: int = 50) -> list:
    """
    查询评论树(路径枚举方案):
    一次查询获取所有评论,按 path 排序即为树形结构
    前端只需根据 level 字段做缩进渲染
    """
    session = Session()
    try:
        offset = (page - 1) * page_size
        rows = session.execute(
            text("""
                SELECT id, parent_id, path, level, user_id, content,
                       like_count, created_at
                FROM comments
                WHERE article_id = :aid AND status = 1
                ORDER BY path, created_at
                LIMIT :limit OFFSET :offset
            """),
            {"aid": article_id, "limit": page_size, "offset": offset}
        ).fetchall()

        return [
            {
                "id": r[0], "parent_id": r[1], "path": r[2],
                "level": r[3], "user_id": r[4], "content": r[5],
                "like_count": r[6], "created_at": str(r[7])
            }
            for r in rows
        ]
    finally:
        session.close()


def add_comment(article_id: int, user_id: int, content: str,
                parent_id: int = 0) -> dict:
    """
    添加评论:
    如果是回复(parent_id > 0),需要继承父评论的 path 并追加自己的 id
    """
    session = Session()
    try:
        if parent_id > 0:
            # 查询父评论的 path 和 level
            parent = session.execute(
                text("SELECT path, level FROM comments WHERE id = :pid"),
                {"pid": parent_id}
            ).fetchone()

            if not parent:
                return {"success": False, "error": "parent_comment_not_found"}

            parent_path = parent[0]  # 如 /1/4/
            parent_level = parent[1]
        else:
            parent_path = "/"
            parent_level = 0

        # 插入评论
        result = session.execute(
            text("""
                INSERT INTO comments (article_id, parent_id, path, level,
                                      user_id, content)
                VALUES (:aid, :pid, '/', :level, :uid, :content)
                RETURNING id
            """),
            {"aid": article_id, "pid": parent_id,
             "level": parent_level + 1, "uid": user_id, "content": content}
        )
        comment_id = result.fetchone()[0]

        # 更新 path: parent_path + comment_id + /
        new_path = f"{parent_path}{comment_id}/"
        session.execute(
            text("UPDATE comments SET path = :path WHERE id = :cid"),
            {"path": new_path, "cid": comment_id}
        )

        # 更新文章评论计数
        session.execute(
            text("UPDATE articles SET comment_count = comment_count + 1 WHERE id = :aid"),
            {"aid": article_id}
        )

        session.commit()
        return {"success": True, "comment_id": comment_id, "path": new_path}

    except Exception as e:
        session.rollback()
        return {"success": False, "error": str(e)}
    finally:
        session.close()


def fulltext_search(keyword: str, page: int = 1, page_size: int = 20) -> list:
    """
    全文搜索(PostgreSQL 方案):
    使用 search_vector 生成列 + GIN 索引
    ts_rank 计算相关性,按权重排序
    """
    session = Session()
    try:
        offset = (page - 1) * page_size
        rows = session.execute(
            text("""
                SELECT id, title, summary, cover_image, published_at,
                       ts_rank(search_vector, plainto_tsquery('simple', :kw)) AS rank
                FROM articles
                WHERE status = 1
                  AND search_vector @@ plainto_tsquery('simple', :kw)
                ORDER BY rank DESC, published_at DESC
                LIMIT :limit OFFSET :offset
            """),
            {"kw": keyword, "limit": page_size, "offset": offset}
        ).fetchall()

        return [
            {
                "id": r[0], "title": r[1], "summary": r[2],
                "cover_image": r[3], "published_at": str(r[4]),
                "rank": float(r[5])
            }
            for r in rows
        ]
    finally:
        session.close()


def fulltext_search_mysql(keyword: str, page: int = 1, page_size: int = 20) -> list:
    """
    全文搜索(MySQL 方案):
    使用 FULLTEXT 索引 + MATCH AGAINST
    注意: 中文需要 ngram 解析器
    """
    session = Session()
    try:
        offset = (page - 1) * page_size
        rows = session.execute(
            text("""
                SELECT id, title, summary, cover_image, published_at,
                       MATCH(title, content) AGAINST(:kw IN NATURAL LANGUAGE MODE) AS score
                FROM articles
                WHERE status = 1
                  AND MATCH(title, content) AGAINST(:kw IN NATURAL LANGUAGE MODE)
                ORDER BY score DESC, published_at DESC
                LIMIT :limit OFFSET :offset
            """),
            {"kw": keyword, "limit": page_size, "offset": offset}
        ).fetchall()

        return [
            {
                "id": r[0], "title": r[1], "summary": r[2],
                "cover_image": r[3], "published_at": str(r[4]),
                "score": float(r[5])
            }
            for r in rows
        ]
    finally:
        session.close()


def get_subtree(category_id: int) -> list:
    """
    查询分类子树(路径枚举方案):
    先获取当前分类的 path,然后用 LIKE 前缀匹配查询所有子分类
    """
    session = Session()
    try:
        # 获取当前分类的 path
        cat = session.execute(
            text("SELECT path FROM categories WHERE id = :cid"),
            {"cid": category_id}
        ).fetchone()

        if not cat:
            return []

        current_path = cat[0]  # 如 /1/2/
        # 查询所有子分类(path 以 current_path 开头的)
        rows = session.execute(
            text("""
                SELECT id, parent_id, name, slug, path, level, sort_order
                FROM categories
                WHERE path LIKE :prefix
                ORDER BY path, sort_order
            """),
            {"prefix": f"{current_path}%"}
        ).fetchall()

        return [
            {
                "id": r[0], "parent_id": r[1], "name": r[2], "slug": r[3],
                "path": r[4], "level": r[5], "sort_order": r[6]
            }
            for r in rows
        ]
    finally:
        session.close()
```

### 10.3.7 全文搜索方案对比

| 特性 | MySQL FULLTEXT | PostgreSQL 全文检索 |
|------|----------------|---------------------|
| 中文支持 | 需要 ngram 解析器 | 需要 simple 或 zhparser 扩展 |
| 权重 | 支持(NATURAL LANGUAGE MODE) | 支持(setweight A/B/C/D 四级) |
| 生成列 | 不支持 | 支持(GENERATED ALWAYS AS) |
| 索引类型 | FULLTEXT INDEX | GIN 索引 |
| 相关性排序 | MATCH ... AGAINST 返回 score | ts_rank 函数 |
| 高亮 | 无原生支持 | ts_headline 函数 |

**PostgreSQL 全文检索更强大**:支持生成列(自动维护 search_vector)、四级权重、高亮显示、以及 `ts_headline` 函数返回带高亮标记的搜索结果片段。

### 10.3.8 关键设计总结

1. **分类树形结构**:路径枚举方案在查询子树时只需一次 LIKE 前缀匹配,性能优于递归查询。但移动节点时需要批量更新子树路径,适合读多写少的场景。
2. **评论无限层级**:路径枚举方案是最佳选择。查询时按 path 排序即可得到完整的树形结构,无需递归。新增评论时只需在父 path 后追加自己的 id。
3. **全文搜索**:PostgreSQL 的全文检索功能远超 MySQL,特别是生成列自动维护索引、四级权重排序、高亮显示等功能。
4. **标签计数冗余**:tags 表中冗余了 usage_count,避免每次查询标签列表时都 JOIN 聚合。需要在添加/删除文章标签时同步更新计数。

## 10.4 SaaS 多租户架构

### 10.4.1 三种多租户方案对比

SaaS(Software as a Service)应用通常需要支持多个租户(tenant),每个租户的数据必须互相隔离。三种主流方案:

| 方案 | 隔离级别 | 数据隔离 | 成本 | 运维复杂度 | 适用场景 |
|------|----------|----------|------|------------|----------|
| 独立数据库 | 最高 | 物理隔离 | 高(每租户一套DB) | 高 | 大客户/合规要求高 |
| 共享DB独立Schema | 中 | Schema级隔离 | 中 | 中 | 中等规模租户 |
| 共享DB共享表 | 低 | tenant_id字段 | 低 | 低 | 小租户/大量租户 |

**推荐**:对于中小型 SaaS 应用,**共享数据库共享表(tenant_id 字段)**方案性价比最高。PostgreSQL 的行级安全(RLS)策略可以在数据库层面强制数据隔离,避免应用层遗漏。

### 10.4.2 共享表方案的设计要点

1. **每张业务表都加 tenant_id 字段**:所有数据行都带有租户标识
2. **所有索引都以 tenant_id 为前缀**:保证查询时先定位到租户,再在租户范围内检索
3. **所有查询都自动注入 tenant_id**:防止跨租户数据泄露
4. **PostgreSQL RLS 策略**:在数据库层面强制隔离,即使 SQL 忘了加 WHERE tenant_id,也不会泄露数据

### 10.4.3 PostgreSQL 建表 SQL(含 RLS 策略)

```sql
-- ============================================================
-- PostgreSQL 14+ SaaS 多租户建表(共享表方案 + RLS)
-- ============================================================

-- 租户表
CREATE TABLE tenants (
    id          BIGSERIAL    PRIMARY KEY,
    name        VARCHAR(100) NOT NULL,
    domain      VARCHAR(255) UNIQUE,    -- 租户自定义域名
    plan        VARCHAR(20)  NOT NULL DEFAULT 'free',  -- free/pro/enterprise
    status      SMALLINT     NOT NULL DEFAULT 1,       -- 0=禁用 1=正常
    max_users   INT          NOT NULL DEFAULT 10,
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

-- 租户用户映射表(一个用户可属于多个租户)
CREATE TABLE tenant_members (
    tenant_id BIGINT NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    user_id   BIGINT NOT NULL,
    role      VARCHAR(20) NOT NULL DEFAULT 'member',  -- owner/admin/member
    joined_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (tenant_id, user_id)
);

-- 业务表: 项目表(所有业务表都带 tenant_id)
CREATE TABLE projects (
    id          BIGSERIAL    PRIMARY KEY,
    tenant_id   BIGINT       NOT NULL REFERENCES tenants(id),
    name        VARCHAR(200) NOT NULL,
    description TEXT,
    owner_id    BIGINT       NOT NULL,
    status      VARCHAR(20)  NOT NULL DEFAULT 'active',
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

-- 业务表: 任务表
CREATE TABLE tasks (
    id          BIGSERIAL    PRIMARY KEY,
    tenant_id   BIGINT       NOT NULL REFERENCES tenants(id),
    project_id  BIGINT       NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    title       VARCHAR(200) NOT NULL,
    description TEXT,
    assignee_id BIGINT,
    status      VARCHAR(20)  NOT NULL DEFAULT 'todo',  -- todo/doing/done
    priority    SMALLINT    NOT NULL DEFAULT 0,
    due_date    DATE,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- ============================================================
-- 多租户索引设计: 所有索引都以 tenant_id 为第一列
-- ============================================================

-- 项目表索引
CREATE INDEX idx_projects_tenant ON projects (tenant_id);
CREATE INDEX idx_projects_tenant_owner ON projects (tenant_id, owner_id);
CREATE INDEX idx_projects_tenant_status ON projects (tenant_id, status);

-- 任务表索引
CREATE INDEX idx_tasks_tenant ON tasks (tenant_id);
CREATE INDEX idx_tasks_tenant_project ON tasks (tenant_id, project_id);
CREATE INDEX idx_tasks_tenant_assignee ON tasks (tenant_id, assignee_id);
CREATE INDEX idx_tasks_tenant_status ON tasks (tenant_id, status, priority);

-- ============================================================
-- 行级安全策略 (Row Level Security, RLS)
-- ============================================================

-- 启用 RLS
ALTER TABLE projects ENABLE ROW LEVEL SECURITY;
ALTER TABLE tasks ENABLE ROW LEVEL SECURITY;

-- 创建策略: 当前会话的 tenant_id 必须与行的 tenant_id 匹配
-- 使用 session variable: current_setting('app.tenant_id')
CREATE POLICY tenant_isolation_projects ON projects
    USING (tenant_id = current_setting('app.tenant_id')::BIGINT);

CREATE POLICY tenant_isolation_tasks ON tasks
    USING (tenant_id = current_setting('app.tenant_id')::BIGINT);

-- 对 tenant_members 表也启用 RLS
ALTER TABLE tenant_members ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation_members ON tenant_members
    USING (tenant_id = current_setting('app.tenant_id')::BIGINT);

-- 注意: 使用 RLS 时,应用需要通过 SET LOCAL app.tenant_id = N 设置当前租户
-- 这个设置应在每个事务开始时执行
```

### 10.4.4 RLS 工作原理

RLS 的核心是:当查询启用了 RLS 的表时,PostgreSQL 会自动在 WHERE 条件中追加策略定义的过滤条件。例如:

```sql
-- 应用层执行的 SQL:
SELECT * FROM projects WHERE status = 'active';

-- PostgreSQL 实际执行的 SQL(RLS 自动追加):
SELECT * FROM projects
WHERE status = 'active'
  AND tenant_id = current_setting('app.tenant_id')::BIGINT;
```

即使开发者忘了加 `WHERE tenant_id = ?`,RLS 也会在数据库层面拦截,确保不会泄露其他租户的数据。

### 10.4.5 Python 代码示例

```python
"""
SaaS 多租户架构 - Python 代码示例
依赖: pip install sqlalchemy psycopg2-binary
"""
from contextvars import ContextVar
from sqlalchemy import create_engine, text, event
from sqlalchemy.orm import sessionmaker, Session

DB_URL = "postgresql+psycopg2://user:pass@localhost:5432/saas"
engine = create_engine(DB_URL, pool_size=10, max_overflow=20, pool_pre_ping=True)
Session = sessionmaker(bind=engine)

# 使用 ContextVar 存储当前请求的 tenant_id(线程安全 + 协程安全)
current_tenant_id: ContextVar[int] = ContextVar("current_tenant_id", default=0)


class TenantContext:
    """
    租户上下文管理器:
    在每个请求开始时设置 tenant_id,请求结束时清除
    配合 RLS 策略自动注入数据隔离
    """
    def __init__(self, tenant_id: int):
        self.tenant_id = tenant_id
        self.token = None
        self.session = None

    def __enter__(self) -> Session:
        self.token = current_tenant_id.set(self.tenant_id)
        self.session = Session()
        # 在事务开始时设置 PostgreSQL session variable
        # RLS 策略会使用这个变量进行数据过滤
        self.session.execute(
            text("SET LOCAL app.tenant_id = :tid"),
            {"tid": self.tenant_id}
        )
        return self.session

    def __exit__(self, exc_type, exc_val, exc_tb):
        if exc_type:
            self.session.rollback()
        else:
            self.session.commit()
        self.session.close()
        current_tenant_id.reset(self.token)


def get_tenant_id_from_request(api_key: str) -> int:
    """
    从 API Key 解析租户 ID
    实际项目中应从 JWT Token 或 API Key 中解析
    """
    session = Session()
    try:
        # 这里简化处理,实际应查询 api_keys 表
        row = session.execute(
            text("SELECT tenant_id FROM tenant_members WHERE user_id = :uid LIMIT 1"),
            {"uid": 1}  # 简化示例
        ).fetchone()
        return row[0] if row else 0
    finally:
        session.close()


def create_project(name: str, description: str, owner_id: int, tenant_id: int) -> dict:
    """
    创建项目(自动注入 tenant_id)
    使用 TenantContext 确保数据隔离
    """
    with TenantContext(tenant_id) as session:
        result = session.execute(
            text("""
                INSERT INTO projects (tenant_id, name, description, owner_id)
                VALUES (:tid, :name, :desc, :owner)
                RETURNING id
            """),
            {"tid": tenant_id, "name": name, "desc": description, "owner": owner_id}
        )
        project_id = result.fetchone()[0]
        return {"success": True, "project_id": project_id}


def list_projects(tenant_id: int, status: str = None) -> list:
    """
    查询项目列表(RLS 自动过滤)
    注意: SQL 中不需要显式写 WHERE tenant_id = ?,RLS 策略会自动追加
    """
    with TenantContext(tenant_id) as session:
        if status:
            rows = session.execute(
                text("""
                    SELECT id, name, description, owner_id, status, created_at
                    FROM projects
                    WHERE status = :status
                    ORDER BY created_at DESC
                """),
                {"status": status}
            ).fetchall()
        else:
            rows = session.execute(
                text("""
                    SELECT id, name, description, owner_id, status, created_at
                    FROM projects
                    ORDER BY created_at DESC
                """)
            ).fetchall()

        return [
            {
                "id": r[0], "name": r[1], "description": r[2],
                "owner_id": r[3], "status": r[4], "created_at": str(r[5])
            }
            for r in rows
        ]


def create_task(tenant_id: int, project_id: int, title: str,
                description: str = None, assignee_id: int = None,
                priority: int = 0) -> dict:
    """创建任务"""
    with TenantContext(tenant_id) as session:
        result = session.execute(
            text("""
                INSERT INTO tasks (tenant_id, project_id, title, description,
                                   assignee_id, priority)
                VALUES (:tid, :pid, :title, :desc, :aid, :pri)
                RETURNING id
            """),
            {"tid": tenant_id, "pid": project_id, "title": title,
             "desc": description, "aid": assignee_id, "pri": priority}
        )
        task_id = result.fetchone()[0]
        return {"success": True, "task_id": task_id}


def get_tenant_usage(tenant_id: int) -> dict:
    """
    获取租户资源使用情况:
    项目数、任务数、成员数等
    """
    with TenantContext(tenant_id) as session:
        project_count = session.execute(
            text("SELECT COUNT(*) FROM projects")
        ).scalar()

        task_count = session.execute(
            text("SELECT COUNT(*) FROM tasks")
        ).scalar()

        member_count = session.execute(
            text("SELECT COUNT(*) FROM tenant_members WHERE tenant_id = :tid"),
            {"tid": tenant_id}
        ).scalar()

        # 获取租户配额
        plan_info = session.execute(
            text("SELECT name, plan, max_users FROM tenants WHERE id = :tid"),
            {"tid": tenant_id}
        ).fetchone()

        return {
            "tenant_name": plan_info[0],
            "plan": plan_info[1],
            "max_users": plan_info[2],
            "project_count": project_count,
            "task_count": task_count,
            "member_count": member_count
        }
```

### 10.4.6 多租户索引设计原则

多租户场景下,索引设计有一个核心原则:**所有复合索引的第一列必须是 tenant_id**。

原因:绝大多数查询都会带 tenant_id 条件,数据库优化器会使用索引的第一列快速定位到目标租户的数据范围,然后在租户内部使用索引后续列进行过滤。如果索引第一列不是 tenant_id,则无法有效利用索引,需要全表扫描后再过滤。

```
-- 错误的索引设计:
CREATE INDEX idx_tasks_status ON tasks (status);        -- 缺少 tenant_id 前缀
CREATE INDEX idx_tasks_assignee ON tasks (assignee_id); -- 缺少 tenant_id 前缀

-- 正确的索引设计:
CREATE INDEX idx_tasks_tenant_status ON tasks (tenant_id, status);
CREATE INDEX idx_tasks_tenant_assignee ON tasks (tenant_id, assignee_id);
```

### 10.4.7 关键设计总结

1. **RLS 是数据库层面的安全网**:即使应用层代码有 bug 漏了 tenant_id 条件,RLS 也会在数据库层面拦截。这是"纵深防御"理念的体现。
2. **ContextVar + SET LOCAL**:Python 端使用 ContextVar 存储当前租户 ID(协程安全),数据库端使用 SET LOCAL 设置会话变量(事务级别),两者配合实现自动隔离。
3. **索引前缀原则**:所有索引以 tenant_id 为第一列,确保查询效率。
4. **大租户拆分**:如果某个租户数据量极大(超过总数据量的 20%),应考虑将其迁移到独立 Schema 或独立数据库,避免影响其他租户的查询性能。

## 10.5 AI 应用数据库设计

### 10.5.1 核心需求分析

AI 应用(尤其是基于大语言模型的应用)对数据库有特殊需求:

- **对话历史存储**:需要按 session 分组存储多轮对话,支持上下文截断
- **向量存储与语义搜索**:将文本向量化后存储,支持相似度检索(RAG 的核心)
- **Prompt 模板管理**:版本控制 + A/B 测试
- **配额与计费**:按 token 用量计费,需要实时计数 + 持久化

### 10.5.2 对话历史表设计

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| session_id | VARCHAR(36) | 会话 ID(UUID) |
| role | VARCHAR(20) | user/assistant/system |
| content | TEXT | 消息内容 |
| token_count | INT | 本条消息的 token 数 |
| model | VARCHAR(50) | 使用的模型(如 gpt-4, qwen-max) |
| metadata | JSONB | 额外元数据(温度、top_p 等) |
| created_at | TIMESTAMPTZ | 创建时间 |

**设计要点**:session_id 使用 UUID,不使用自增 ID,因为对话 ID 经常暴露给前端,UUID 不可猜测。token_count 字段用于计费和上下文截断——当累积 token 数超过模型上下文窗口时,自动截断早期消息。


### 10.5.4 向量索引方案对比

| 索引类型 | 原理 | 构建速度 | 查询速度 | 召回率 | 适用场景 |
|----------|------|----------|----------|--------|----------|
| 精确搜索 | 全表扫描 | 无需构建 | 慢(O(N)) | 100% | 数据量小(<10万) |
| IVFFlat | 倒排文件+聚类 | 快 | 快 | 中等 | 中等规模 |
| HNSW | 层次化小世界图 | 慢 | 极快 | 高 | 大规模(推荐) |

**推荐 HNSW 索引**:构建速度虽慢,但查询速度极快且召回率高,适合实时语义搜索。参数 `m=16`(每个节点的最大连接数)和 `ef_construction=64`(构建时搜索宽度)是常用的平衡配置。

```python
def get_chat_history(session_id: str, max_tokens: int = 4096) -> list:
    """
    获取对话历史(带 token 截断):
    从最新消息开始倒序读取,累积 token 数不超过 max_tokens

    try:
        rows = session.execute(
            text("""
                SELECT id, role, content, token_count, model, created_at
                FROM chat_messages
                WHERE session_id = :sid
                ORDER BY id DESC
            """),
            {"sid": session_id}
        ).fetchall()

        # 从最新消息开始累积,超过 max_tokens 则截断
        messages = []
        accumulated = 0
        for r in reversed(rows):
            if accumulated + r[3] > max_tokens:
                break
            messages.append({
                "role": r[1],
                "content": r[2],
                "token_count": r[3]
            })
            accumulated += r[3]

        return messages
    finally:
        session.close()

def index_document(document_id: int, chunks: list):
    """
    将文档分块后向量化并存储:
    chunks: [{"content": "...", "token_count": 100}, ...]
    """
    session = Session()
    try:
        for i, chunk in enumerate(chunks):
            # 获取向量
            embedding = get_embedding(chunk["content"])

            # 将向量转为字符串格式: "[0.1, 0.2, ...]"
            embedding_str = "[" + ",".join(str(x) for x in embedding) + "]"

            session.execute(

                        (document_id, chunk_index, content, embedding, token_count)
                    VALUES (:did, :idx, :content, :emb::vector, :tokens)
                """),

                    "did": document_id, "idx": i,
                    "content": chunk["content"],
                    "emb": embedding_str,
                    "tokens": chunk.get("token_count", 0)
                }
            )

        session.execute(
            text("""
                UPDATE knowledge_documents
                SET status = 'ready', chunk_count = :count, updated_at = NOW()
                WHERE id = :did
            """),
            {"did": document_id, "count": len(chunks)}
        )

        session.commit()
    except Exception as e:
        session.rollback()
        raise e
    finally:
        session.close()


def semantic_search(query: str, top_k: int = 5, score_threshold: float = 0.75) -> list:
    """
    语义搜索:
    1. 将查询文本向量化
    2. 在 knowledge_chunks 表中进行向量相似度搜索
    3. 返回最相关的 top_k 个文本块
    """
    # 获取查询向量
    query_embedding = get_embedding(query)
    embedding_str = "[" + ",".join(str(x) for x in query_embedding) + "]"

    session = Session()
    try:
        rows = session.execute(
            text("""
                SELECT c.id, c.content, c.token_count,
                       d.title AS doc_title,
                       1 - (c.embedding <=> :emb::vector) AS similarity
                FROM knowledge_chunks c
                JOIN knowledge_documents d ON d.id = c.document_id
                WHERE d.status = 'ready'
                  AND 1 - (c.embedding <=> :emb::vector) > :threshold
                ORDER BY c.embedding <=> :emb::vector
                LIMIT :k
            """),
            {"emb": embedding_str, "k": top_k, "threshold": score_threshold}
        ).fetchall()

        return [
            {
                "chunk_id": r[0],
                "content": r[1],
                "token_count": r[2],
                "doc_title": r[3],
                "similarity": float(r[4])
            }
            for r in rows
        ]
    finally:
        session.close()

def get_prompt_template(name: str) -> dict:
    """
    获取 Prompt 模板:
    如果有 A/B 测试实验,根据权重随机选择版本
    否则返回活跃版本
    """
    session = Session()
    try:
        # 查找实验版本
        experiments = session.execute(
            text("""
                SELECT id, name, version, system_prompt, user_prompt,
                       variables, model, temperature, max_tokens,
                       experiment_weight
                FROM prompt_templates
                WHERE name = :name AND is_active = true AND is_experiment = true
                  AND experiment_weight > 0
            """),
            {"name": name}
        ).fetchall()

        if experiments:
            # 按 weight 加权随机选择
            import random
            total_weight = sum(e[9] for e in experiments)
            rand = random.uniform(0, total_weight)
            cumulative = 0
            selected = experiments[0]
            for exp in experiments:
                cumulative += exp[9]
                if rand <= cumulative:
                    selected = exp
                    break
            exp = selected
        else:
            # 返回活跃的非实验版本
            exp = session.execute(
                text("""
                    SELECT id, name, version, system_prompt, user_prompt,
                           variables, model, temperature, max_tokens
                    FROM prompt_templates
                    WHERE name = :name AND is_active = true AND is_experiment = false
                    ORDER BY version DESC
                    LIMIT 1
                """),
                {"name": name}
            ).fetchone()

        if not exp:
            return {"success": False, "error": "template_not_found"}

        return {
            "success": True,
            "id": exp[0],
            "name": exp[1],
            "version": exp[2],
            "system_prompt": exp[3],
            "user_prompt": exp[4],
            "variables": json.loads(exp[5]) if exp[5] else [],
            "model": exp[6],
            "temperature": float(exp[7]),
            "max_tokens": exp[8]
        }
    finally:
        session.close()

# 用户配额管理 (Redis 实时计数 + 数据库持久化)
# ============================================================
def check_and_deduct_quota(user_id: int, input_tokens: int,
                           output_tokens: int, model: str) -> dict:
    """
    配额检查与扣减(Redis 实时计数 + 数据库持久化):

    流程:
    1. 从 Redis 读取当日/当月已用 token 数
    2. 检查是否超过配额
    3. 如果未超限,Redis 原子扣减
    4. 异步写入数据库持久化(用量记录 + 配额更新)
    """
    total_tokens = input_tokens + output_tokens

    # Redis key
    daily_key = f"quota:user:{user_id}:daily:{date.today().isoformat()}"
    monthly_key = f"quota:user:{user_id}:monthly:{date.today().strftime('%Y-%m')}"

    # 从 Redis 获取当前用量(使用 pipeline 批量操作)
    pipe = rds.pipeline()
    pipe.get(daily_key)
    pipe.get(monthly_key)
    daily_used, monthly_used = pipe.execute()

    daily_used = int(daily_used or 0)
    monthly_used = int(monthly_used or 0)

    # 从数据库获取配额限制
    session = Session()
    try:
        quota = session.execute(
            text("""
                SELECT daily_token_limit, monthly_token_limit,
                       used_today, used_this_month
                FROM user_quotas WHERE user_id = :uid
            """),
            {"uid": user_id}
        ).fetchone()

        if not quota:
            # 用户没有配额记录,创建默认配额
            session.execute(
                text("""
                    INSERT INTO user_quotas (user_id) VALUES (:uid)
                """),
                {"uid": user_id}
            )
            session.commit()
            daily_limit = 100000
            monthly_limit = 3000000
        else:
            daily_limit = quota[0]
            monthly_limit = quota[1]

        # 检查配额
        if daily_used + total_tokens > daily_limit:
            return {"success": False, "error": "daily_quota_exceeded",
                    "used": daily_used, "limit": daily_limit}

        if monthly_used + total_tokens > monthly_limit:
            return {"success": False, "error": "monthly_quota_exceeded",
                    "used": monthly_used, "limit": monthly_limit}

        # Redis 原子扣减(使用 pipeline)
        pipe = rds.pipeline()
        pipe.incrby(daily_key, total_tokens)
        pipe.incrby(monthly_key, total_tokens)
        # 设置过期时间(每日 key 保留2天,每月 key 保留35天)
        pipe.expire(daily_key, 86400 * 2)
        pipe.expire(monthly_key, 86400 * 35)
        pipe.execute()

        # 数据库持久化: 记录用量日志
        # 费用计算(简化: input $0.03/1K, output $0.06/1K, 转为分)
        cost_cents = (input_tokens * 0.03 + output_tokens * 0.06) / 10
        session.execute(
            text("""
                INSERT INTO token_usage_logs
                    (user_id, model, input_tokens, output_tokens,
                     total_tokens, cost_cents)
                VALUES (:uid, :model, :in_tok, :out_tok, :total, :cost)
            """),
            {"uid": user_id, "model": model,
             "in_tok": input_tokens, "out_tok": output_tokens,
             "total": total_tokens, "cost": cost_cents}
        )

        # 更新配额累计(使用 Redis 的值,避免并发覆盖)
        session.execute(
            text("""
                UPDATE user_quotas
                SET used_today = :daily, used_this_month = :monthly,
                    updated_at = NOW()
                WHERE user_id = :uid
            """),
            {"uid": user_id,
             "daily": daily_used + total_tokens,
             "monthly": monthly_used + total_tokens}
        )
        session.commit()

        return {
            "success": True,
            "total_tokens": total_tokens,
            "daily_used": daily_used + total_tokens,
            "daily_limit": daily_limit
        }

    except Exception as e:
        session.rollback()
        return {"success": False, "error": str(e)}
    finally:
        session.close()
```

### 10.5.6 pgvector 查询语法说明

pgvector 扩展提供了几个关键的向量操作符:

| 操作符 | 说明 | 距离类型 |
|--------|------|----------|
| `<->` | 欧几里得距离 (L2) | 越小越相似 |
| `<=>` | 余弦距离 | 越小越相似(0=完全相同) |
| `<#>` | 负内积 | 越小越相似 |

语义搜索中常用余弦距离 `<=>`。相似度 = 1 - 余弦距离,值越大越相似。

```sql
-- 查询最相似的5个文本块
SELECT id, content,
       1 - (embedding <=> '[0.1, 0.2, ...]'::vector) AS similarity
FROM knowledge_chunks
ORDER BY embedding <=> '[0.1, 0.2, ...]'::vector
LIMIT 5;
```

### 10.5.7 关键设计总结

1. **对话历史与 token 截断**:chat_messages 表按 session_id 分组,查询时从最新消息开始倒序累积 token 数,超过模型上下文窗口时自动截断早期消息。这样可以控制传给模型的上下文长度,避免超出 token 限制。
2. **pgvector + HNSW 索引**:向量维度取决于嵌入模型(OpenAI ada-002 为 1536 维)。HNSW 索引查询速度极快,适合实时 RAG 场景。构建时可适当调大 `ef_construction` 以提高召回率。
3. **Prompt 模板版本管理**:通过 (name, version) 唯一约束保证版本唯一。A/B 测试通过 `is_experiment` 和 `experiment_weight` 实现,运行时按权重加权随机选择版本。
4. **配额计费双写策略**:Redis 实时计数(高性能、原子操作),数据库定期持久化(可审计、可分析)。Redis key 设置 TTL 自动过期,避免无限增长。
5. **LangChain SQL Agent**:通过自然语言直接查询数据库是 AI 应用的热门方向,但需注意权限控制——只暴露必要的表给 Agent,并限制返回行数(top_k)。

## 10.6 日志与审计系统

### 10.6.1 核心需求分析

日志与审计系统是生产环境中不可或缺的基础设施,需要解决以下问题:

- **操作日志**:记录"谁在什么时候做了什么操作",用于行为追踪和问题排查
- **审计追踪**:记录数据的字段级变更(旧值 -> 新值),用于合规审计
- **日志归档**:日志数据量极大,需要按时间分区,便于过期清理
- **性能优化**:热日志(近期)缓存到 Redis,冷日志(历史)存数据库

### 10.6.7 Python 代码示例

```python
"""
日志与审计系统 - Python 代码示例
依赖: pip install sqlalchemy psycopg2-binary redis
"""
import json
import time
from datetime import datetime, timedelta
from sqlalchemy import create_engine, text
from sqlalchemy.orm import sessionmaker
import redis

DB_URL = "postgresql+psycopg2://user:pass@localhost:5432/logs"
engine = create_engine(DB_URL, pool_size=10, max_overflow=20, pool_pre_ping=True)
Session = sessionmaker(bind=engine)
rds = redis.Redis(host="localhost", port=6379, db=0, decode_responses=True)


def log_operation(user_id: int, action: str, resource_type: str,
                  resource_id: str = None, ip_address: str = None,
                  user_agent: str = None, request_method: str = None,
                  request_path: str = None, request_params: dict = None,
                  response_status: int = None, duration_ms: int = None,
                  error_message: str = None):
    """
    记录操作日志:
    1. 写入 Redis 热日志(最近7天可查)
    2. 异步批量写入数据库(冷日志持久化)
    """
    log_entry = {
        "user_id": user_id,
        "action": action,
        "resource_type": resource_type,
        "resource_id": resource_id,
        "ip_address": ip_address,
        "user_agent": user_agent,
        "request_method": request_method,
        "request_path": request_path,
        "request_params": json.dumps(request_params) if request_params else None,
        "response_status": response_status,
        "duration_ms": duration_ms,
        "error_message": error_message,
        "created_at": datetime.utcnow().isoformat()
    }

    # 写入 Redis 热日志(List 结构,保留最近 N 条)
    log_key = f"oplog:hot:{datetime.utcnow().strftime('%Y%m%d')}"
    rds.lpush(log_key, json.dumps(log_entry))
    rds.expire(log_key, 86400 * 7)  # 7天过期

    # 同时写入 Redis Stream(供消费者异步批量写入数据库)
    rds.xadd("oplog:stream", log_entry, maxlen=10000)


def flush_operation_logs():
    """
    批量将 Redis Stream 中的日志写入数据库
    应由定时任务或后台消费者调用
    """
    session = Session()
    try:
        # 从 Redis Stream 读取日志(每次最多100条)
        streams = rds.xread({"oplog:stream": "0"}, count=100, block=1000)
        if not streams:
            return {"flushed": 0}

        entries = streams[0][1]  # [(id, {fields}), ...]
        batch_values = []
        stream_ids = []

        for entry_id, fields in entries:
            stream_ids.append(entry_id)
            batch_values.append({
                "user_id": fields.get("user_id"),
                "action": fields.get("action"),
                "resource_type": fields.get("resource_type"),
                "resource_id": fields.get("resource_id"),
                "ip_address": fields.get("ip_address"),
                "user_agent": fields.get("user_agent"),
                "request_method": fields.get("request_method"),
                "request_path": fields.get("request_path"),
                "request_params": fields.get("request_params"),
                "response_status": int(fields["response_status"]) if fields.get("response_status") else None,
                "duration_ms": int(fields["duration_ms"]) if fields.get("duration_ms") else None,
                "error_message": fields.get("error_message"),
            })

        # 批量插入数据库
        for v in batch_values:
            session.execute(
                text("""
                    INSERT INTO operation_logs
                        (user_id, action, resource_type, resource_id,
                         ip_address, user_agent, request_method, request_path,
                         request_params, response_status, duration_ms,
                         error_message)
                    VALUES (:user_id, :action, :resource_type, :resource_id,
                            :ip_address, :user_agent, :request_method, :request_path,
                            :request_params, :response_status, :duration_ms,
                            :error_message)
                """),
                v
            )

        session.commit()

        # 从 Stream 中删除已处理的条目
        if stream_ids:
            rds.xdel("oplog:stream", *stream_ids)

        return {"flushed": len(batch_values)}

    except Exception as e:
        session.rollback()
        return {"flushed": 0, "error": str(e)}
    finally:
        session.close()


def record_audit_trail(table_name: str, record_id: str, operation: str,
                       changes: dict, changed_by: int):
    """
    记录审计追踪(字段级变更):
    changes: {"field_name": {"old": "old_val", "new": "new_val"}, ...}
    """
    session = Session()
    try:
        for field_name, change in changes.items():
            session.execute(
                text("""
                    INSERT INTO audit_trail
                        (table_name, record_id, operation, field_name,
                         old_value, new_value, changed_by)
                    VALUES (:tbl, :rid, :op, :field, :old, :new, :by)
                """),
                {
                    "tbl": table_name, "rid": record_id,
                    "op": operation, "field": field_name,
                    "old": str(change["old"]) if change["old"] is not None else None,
                    "new": str(change["new"]) if change["new"] is not None else None,
                    "by": changed_by
                }
            )
        session.commit()
    except Exception as e:
        session.rollback()
        raise e
    finally:
        session.close()


def update_with_audit(table_name: str, record_id: str, updates: dict,
                      changed_by: int):
    """
    带审计追踪的更新操作:
    1. 查询旧值
    2. 比较差异
    3. 执行更新
    4. 记录审计
    """
    session = Session()
    try:
        # 查询旧值
        columns = ", ".join(updates.keys())
        old_row = session.execute(
            text(f"SELECT {columns} FROM {table_name} WHERE id = :rid"),
            {"rid": record_id}
        ).fetchone()

        if not old_row:
            return {"success": False, "error": "record_not_found"}

        # 比较差异
        changes = {}
        old_dict = dict(zip(updates.keys(), old_row))
        for field, new_val in updates.items():
            old_val = old_dict[field]
            if str(old_val) != str(new_val):
                changes[field] = {"old": old_val, "new": new_val}

        if not changes:
            return {"success": True, "message": "no_changes"}

        # 执行更新
        set_clauses = ", ".join(f"{k} = :{k}" for k in changes.keys())
        params = {k: v["new"] for k, v in changes.items()}
        params["rid"] = record_id

        session.execute(
            text(f"UPDATE {table_name} SET {set_clauses} WHERE id = :rid"),
            params
        )

        # 记录审计
        record_audit_trail(table_name, record_id, "UPDATE", changes, changed_by)

        session.commit()
        return {"success": True, "changed_fields": list(changes.keys())}

    except Exception as e:
        session.rollback()
        return {"success": False, "error": str(e)}
    finally:
        session.close()


def query_audit_history(table_name: str, record_id: str,
                        start_date: datetime = None,
                        end_date: datetime = None) -> list:
    """
    查询某条记录的完整审计历史:
    用于展示"该记录的所有变更记录"
    """
    session = Session()
    try:
        params = {"tbl": table_name, "rid": record_id}

        date_filter = ""
        if start_date:
            date_filter += " AND changed_at >= :start"
            params["start"] = start_date
        if end_date:
            date_filter += " AND changed_at < :end"
            params["end"] = end_date

        rows = session.execute(
            text(f"""
                SELECT id, table_name, record_id, operation, field_name,
                       old_value, new_value, changed_by, changed_at
                FROM audit_trail
                WHERE table_name = :tbl AND record_id = :rid
                {date_filter}
                ORDER BY changed_at ASC
            """),
            params
        ).fetchall()

        return [
            {
                "id": r[0], "table_name": r[1], "record_id": r[2],
                "operation": r[3], "field_name": r[4],
                "old_value": r[5], "new_value": r[6],
                "changed_by": r[7], "changed_at": str(r[8])
            }
            for r in rows
        ]
    finally:
        session.close()


def search_operation_logs(user_id: int = None, action: str = None,
                          resource_type: str = None,
                          start_date: datetime = None,
                          end_date: datetime = None,
                          page: int = 1, page_size: int = 20) -> dict:
    """
    检索操作日志:
    1. 先查 Redis 热日志(最近7天)
    2. 再查数据库冷日志
    3. 合并结果返回
    """
    results = []

    # 1. 查 Redis 热日志
    if not start_date or start_date >= datetime.utcnow() - timedelta(days=7):
        hot_key = f"oplog:hot:{datetime.utcnow().strftime('%Y%m%d')}"
        raw_logs = rds.lrange(hot_key, 0, page_size - 1)
        for raw in raw_logs:
            log = json.loads(raw)
            if user_id and log.get("user_id") != user_id:
                continue
            if action and log.get("action") != action:
                continue
            if resource_type and log.get("resource_type") != resource_type:
                continue
            results.append(log)

    # 2. 查数据库冷日志
    session = Session()
    try:
        conditions = []
        params = {}

        if user_id:
            conditions.append("user_id = :uid")
            params["uid"] = user_id
        if action:
            conditions.append("action = :act")
            params["act"] = action
        if resource_type:
            conditions.append("resource_type = :rt")
            params["rt"] = resource_type
        if start_date:
            conditions.append("created_at >= :start")
            params["start"] = start_date
        if end_date:
            conditions.append("created_at < :end")
            params["end"] = end_date

        where_clause = " AND ".join(conditions) if conditions else "1=1"
        offset = (page - 1) * page_size

        rows = session.execute(
            text(f"""
                SELECT id, user_id, action, resource_type, resource_id,
                       ip_address, request_method, request_path,
                       response_status, duration_ms, error_message, created_at
                FROM operation_logs
                WHERE {where_clause}
                ORDER BY created_at DESC
                LIMIT :limit OFFSET :offset
            """),
            {**params, "limit": page_size, "offset": offset}
        ).fetchall()

        db_results = [
            {
                "id": r[0], "user_id": r[1], "action": r[2],
                "resource_type": r[3], "resource_id": r[4],
                "ip_address": str(r[5]) if r[5] else None,
                "request_method": r[6], "request_path": r[7],
                "response_status": r[8], "duration_ms": r[9],
                "error_message": r[10], "created_at": str(r[11])
            }
            for r in rows
        ]

        results.extend(db_results)
        return {"logs": results, "total": len(results), "page": page}

    finally:
        session.close()


def auto_maintenance_partitions():
    """
    分区自动维护脚本:
    1. 创建下个月的分区(如果不存在)
    2. 归档超过 N 个月的旧分区
    应由定时任务每月执行一次
    """
    session = Session()
    try:
        # 下个月的年份和月份
        next_month = datetime.utcnow().replace(day=1) + timedelta(days=32)
        next_month = next_month.replace(day=1)
        partition_name = f"operation_logs_{next_month.strftime('%Y%m')}"
        start_date = next_month.strftime('%Y-%m-%d')
        end_date = (next_month + timedelta(days=32)).replace(day=1).strftime('%Y-%m-%d')

        # 检查分区是否已存在
        exists = session.execute(
            text("""
                SELECT 1 FROM pg_tables
                WHERE tablename = :name
            """),
            {"name": partition_name}
        ).fetchone()

        if not exists:
            session.execute(
                text(f"""
                    CREATE TABLE {partition_name} PARTITION OF operation_logs
                    FOR VALUES FROM ('{start_date}') TO ('{end_date}')
                """)
            )
            session.commit()
            print(f"Created partition: {partition_name}")
        else:
            print(f"Partition already exists: {partition_name}")

        # 归档6个月前的分区
        archive_before = datetime.utcnow() - timedelta(days=180)
        old_partition = f"operation_logs_{archive_before.strftime('%Y%m')}"

        old_exists = session.execute(
            text("SELECT 1 FROM pg_tables WHERE tablename = :name"),
            {"name": old_partition}
        ).fetchone()

        if old_exists:
            # 分离旧分区(数据保留在独立表中,可导出归档后删除)
            session.execute(
                text(f"ALTER TABLE operation_logs DETACH PARTITION {old_partition}")
            )
            session.commit()
            print(f"Detached old partition: {old_partition}")

    except Exception as e:
        session.rollback()
        print(f"Error: {e}")
    finally:
        session.close()
```

### 10.6.8 日志冷热分离架构

```
请求 -> log_operation()
           |
           +-> Redis Stream (oplog:stream)  -- 异步缓冲队列
           |
           +-> Redis List (oplog:hot:YYYYMMDD) -- 热日志,7天过期
                    |
                    v
           flush_operation_logs()  -- 定时批量消费
                    |
                    v
           PostgreSQL 分区表 (operation_logs_YYYYMM) -- 冷日志持久化
                    |
                    v
           auto_maintenance_partitions() -- 定期归档
                    |
                    v
           DETACH -> pg_dump -> DROP -- 归档清理
```

**设计要点**:
1. Redis 充当缓冲层,避免日志写入阻塞业务请求
2. Redis List 存热日志(7天),支持即时查询
3. Redis Stream 作为异步队列,消费者批量写入数据库
4. 数据库按月分区,查询自动路由到对应分区,无需全表扫描
5. 超过保留期限的分区被 DETACH 后导出归档,再 DROP 释放空间

### 10.6.9 关键设计总结

1. **分区表是日志系统的核心**:操作日志和审计日志的数据量随时间线性增长,如果不分区,单表数据量很快就会达到千万甚至亿级,查询性能急剧下降。按月分区后,查询自动路由到目标分区,只需扫描单月数据。

2. **分区表主键必须包含分区键**:PostgreSQL 要求分区键必须包含在主键中,因此 `PRIMARY KEY (id, created_at)` 是标准做法。MySQL 的 RANGE 分区同样要求分区键在唯一索引中。

3. **冷热分离架构**:Redis 存热日志(7天,高频查询),数据库存冷日志(全量,低频查询)。写入时先写 Redis(非阻塞),异步消费写入数据库。这避免了日志写入成为业务请求的性能瓶颈。

4. **审计追踪的通用性**:audit_trail 表设计为通用结构,不绑定具体业务表。通过 table_name + record_id 定位到任意表的任意记录,field_name 记录具体变更字段。INSERT 和 DELETE 操作的 field_name 可为空(整条记录的新增/删除)。

5. **分区自动维护**:通过定时任务(如 pg_cron 或外部调度器)每月执行一次分区维护:创建下月分区 + 归档过期分区。这是分区表方案的运维成本所在,但相比不分区的全表扫描性能提升,这个成本是值得的。

## 本章总结

本章覆盖了六大实战业务场景,每个场景都涉及了不同的数据库设计模式和技术难点:

| 场景 | 核心知识点 | 关键技术 |
|------|-----------|----------|
| 10.1 用户认证与权限 | RBAC 五表模型, JWT 吊销, OAuth2 绑定 | bcrypt 密码哈希, Redis 白名单 |
| 10.2 电商商品与订单 | SPU/SKU 模型, 乐观锁库存扣减, 支付幂等 | 乐观锁, Redis Lua 预扣减, 事务号唯一约束 |
| 10.3 内容管理系统 | 树形分类, 路径枚举评论树, 全文搜索 | 路径枚举, PostgreSQL tsvector, MySQL FULLTEXT |
| 10.4 SaaS 多租户 | tenant_id 隔离, RLS 行级安全, 索引前缀 | PostgreSQL RLS 策略, SET LOCAL, ContextVar |
| 10.5 AI 应用 | 对话历史截断, pgvector 语义搜索, 配额计费 | pgvector + HNSW, Redis 实时计数, Prompt A/B 测试 |
| 10.6 日志与审计 | 分区表归档, 字段级审计, 冷热分离 | RANGE 分区, Redis Stream 异步消费, DETACH 归档 |

**贯穿所有场景的核心原则**:

1. **数据完整性优先**:外键约束、唯一约束、CHECK 约束、NOT NULL 约束应在数据库层面保证,不要只依赖应用层校验。
2. **索引设计面向查询**:先确定高频查询模式,再设计索引。复合索引的列顺序遵循"最左前缀"原则,高选择性列在前,等值条件列在前。
3. **读写分离与冷热分层**:Redis 承担高频读写和实时计数,数据库承担持久化和复杂查询。两者配合而非替代。
4. **幂等性设计**:涉及支付、回调、重试的场景,必须通过唯一约束(事务号)或状态机(状态校验)保证幂等。
5. **安全纵深防御**:密码哈希(bcrypt)在应用层,数据隔离(RLS)在数据库层,权限检查(RBAC)在业务层。每一层都不可省略。
