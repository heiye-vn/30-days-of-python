### 一、性能问题

#### 1. 避免在循环内做重复计算

```python
# ❌ 每次循环都调用 len()
for i in range(len(data)):
    process(data[i])

# ✅ 提前缓存
n = len(data)
for i in range(n):
    process(data[i])

# ✅ 更 Pythonic：直接遍历
for item in data:
    process(item)
```

#### 2. 避免在循环内频繁拼接字符串

```python
# ❌ 每次 += 都创建新字符串对象，O(n²) 复杂度
result = ""
for word in words:
    result += word + " "

# ✅ 用 join，一次完成
result = " ".join(words)
```

#### 3. 能用内置函数就不手写循环

```python
# ❌ 手写求和
total = 0
for n in numbers:
    total += n

# ✅ 内置函数底层是 C，快得多
total = sum(numbers)
max_val = max(numbers)
filtered = list(filter(lambda x: x > 0, numbers))
```

#### 4.不要在循环里频繁操作数据库

```python
# ❌ 如果需要插入大量用户，则会执行多次 sql，会很慢
for user in users:
    db.insert(user)

# ✅ 批量插入，减少 I/O 次数
db.insert_many(users)

# 或者
batch = []
for user in users:
    batch.append(user)
db.insert_many(batch)

# 或者 ORM 自带的批量插入方法
bulk_create()
```

#### 5. 不要在循环里频繁请求网络

```python
# ❌ 多个请求会阻塞
for url in urls:
    requests.get(url)

# ✅ 使用 asyncio 或者 ThreadPoolExecutor


```

### 二、循环中修改正在遍历的集合（高危！）

这是最常见的 bug 来源之一：

```python
# ❌ 边遍历边删除列表，下标会错位，漏掉元素
nums = [1, 2, 3, 4, 5]
for n in nums:
    if n % 2 == 0:
        nums.remove(n)
# 结果是 [1, 3, 5]？不对，实际是 [1, 3, 5] 看似正常
# 但换成 [1, 2, 3, 4] 就会漏掉 3

# ✅ 方案一：遍历副本
for n in nums[:]:
    if n % 2 == 0:
        nums.remove(n)

# ✅ 方案二：推导式生成新列表（推荐）
nums = [n for n in nums if n % 2 != 0]
```

字典同理：

```python
# ❌ Python 3 会直接抛 RuntimeError
for key in d:
    if key.startswith("tmp_"):
        del d[key]

# ✅ 遍历 keys 的副本
for key in list(d.keys()):
    if key.startswith("tmp_"):
        del d[key]
```

### 三、while 循环要防止死循环

```python
# ❌ 忘记更新条件变量
count = 0
while count < 10:
    print(count)
    # 忘写 count += 1，死循环！

# ✅ 加超时或最大次数保护（网络重试场景常见）
MAX_RETRIES = 3
retries = 0
while retries < MAX_RETRIES:
    try:
        result = call_api()
        break
    except Exception:
        retries += 1
```

### 四、嵌套循环的复杂度意识

双层循环是 O(n²)，数据量大时会很慢：

```python
# ❌ O(n²)：在列表里查找交集
common = []
for a in list_a:
    for b in list_b:
        if a == b:
            common.append(a)

# ✅ O(n)：先转 set，查找变 O(1)
set_b = set(list_b)
common = [a for a in list_a if a in set_b]
```

**一个实用的经验法则**： 如果循环里有 if x in some_list，几乎总应该把那个 list 换成 set。

### 五、循环变量泄漏（Python 特性，需注意）

Python 的 `for` 循环变量在循环结束后依然存在：

```python
for i in range(5):
    pass
print(i)  # 输出 4，变量没有被销毁

# 实际开发中容易误用：
for item in data:
    last = item

# 循环后 item 和 last 都还活着，可能干扰后续逻辑
# 养成习惯：不依赖循环变量的最终值，或显式重置
```

### 六、RAG / AI 开发中的循环常见坑

**批量调用 API 时别忘了限速**

```python
import time

# ❌ 无限速，触发 rate limit
for chunk in chunks:
    embed = openai.embed(chunk)

# ✅ 加间隔，或用 asyncio 控制并发数
for i, chunk in enumerate(chunks):
    embed = openai.embed(chunk)
    if i % 10 == 9:  # 每 10 条暂停一下
        time.sleep(1)
```

**批量入库用批次，别逐条 insert**

```python
# ❌ 每条单独写数据库，N 次 I/O
for vec in vectors:
    db.insert(vec)

# ✅ 分批写入，减少 I/O 次数
BATCH_SIZE = 100
for i in range(0, len(vectors), BATCH_SIZE):
    batch = vectors[i: i + BATCH_SIZE]
    db.bulk_insert(batch)
```

### 七、Code Review 检查清单

在审查涉及循环的代码时，逐项确认：

- [ ] 循环内是否有 O(n) 操作？能否预处理为 O(1)？
- [ ] 是否有无限循环风险？有无安全退出机制？
- [ ] 是否在遍历中修改了被遍历对象？
- [ ] 大数据是否使用了惰性求值/流式处理？
- [ ] I/O 操作是否做了批量化？
- [ ] 异常处理是否精确？是否有日志/监控？
- [ ] 循环变量是否在闭包中被错误引用？
- [ ] 是否有对应的单元测试覆盖边界情况？

> 看到循环就思考复杂度"的习惯，能规避绝大多数线上问题。
